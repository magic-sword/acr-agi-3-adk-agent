# Reusing a witnessed procedure

Use when `procedures` contains a candidate whose achieved relationship resembles the current subgoal. No candidate means there is nothing to reuse.

1. Read its source level, cause, steps, effects and invariants. Determine what was actually witnessed. A short history segment or one success does not prove all steps were necessary or sufficient.
2. Compare current control mode, object roles, access and required conditions with the source. Match relationships rather than raw coordinates. Similar colors across levels do not establish identical roles.
3. Rebind only targets supported by current evidence. Identify assumptions that transferred and those requiring a fresh test. Discard the candidate if its essential condition cannot be verified or tested within the remaining budget.
4. Convert the applicable remainder into a normal conditional plan with observable checkpoints and invariants. Revalidate after each external action; do not replay an action sequence blindly or generate executable code.
5. If a checkpoint fails, diagnose the changed assumption and repair the remainder. Report the evidence against applicability; preserve unrelated procedures as candidates.

Example: a previous route moved a support aside before collecting an item. In a mirrored layout, reuse the ordering only after identifying the current support and reachable staging space. Replaying the old LEFT input or click coordinates is not an adaptation.

The host records successful fragments during consolidation. This skill proposes an adapted plan; it does not write new Skill files or claim a game-independent learned rule.
