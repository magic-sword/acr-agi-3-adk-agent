# 自律スキル学習の実装

2026-09-25。現行仕様。設計理由・参考文献・今回の検証は[小目標と実験ループ](goal-experiment-loop-design-ja.md)。スキル学習の背景は[初期設計](autonomous-skill-learning-design-ja.md)。

## 実行

ADK Workflowの制御骨格は `DECIDE → RUN → 必要時DECIDE`。仕事は次の三種類を直列に切り替える。一冊の攻略ノートが目標・実験の正本であり、仕事ごとの独立した記憶は作らない。

|仕事|入力と出力|
|---|---|
|`experiment_design`|現在の目標経路・直近判定から、小目標と一回の実験を設計。`submit_decision`で操作・スキル利用等を選択|
|`experiment_review`|固定した予測・受付・前後観測を比較。画素／レベル条件はホスト判定。意味判定では`submit_review`だけを完了ツールとして公開|
|`skill_creation`|選択した実経験から`propose_skill`。不足情報があれば`defer_skill`で設計へ戻る。直接操作はできない|

`act`には`purpose / action / experiment`が必要。実験は小目標（親ID・完了条件）、問い、条件付き仮説、期待する観測を持つ。ホストが操作前にノートへ保存し、操作のID・実験ID・前後観測・実経験・判定を関連付ける。予測や判定条件は後から書き換えられない。

期待は `region_changed`（指定矩形で一つ以上の画素が変わる）、`level_increased`、`semantic`（指定範囲の意味的な変化）の三種類。領域は元画像のx・y・width・height。別領域にある前提条件は任意の`context_region`で宣言できる。観測期間は次の実観測まで。画素変化の支持は因果関係や攻略進捗の証明ではない。

結果は `supported / unsupported / inconclusive`、根拠となる実経験ID、小目標の状態、次への更新を記録する。小目標の達成と仮説の支持は別。ホストの単純な画素・レベル判定は小目標を勝手に完了せず、次の設計へ測定値を返す。意味判定ではモデルが小目標の完了条件も評価する。未判定の実験がある間は次の操作へ進まない。最後の操作も予算・勝利停止前に判定し、時間不足・終了で判定できなければ中断として残す。

同じ操作・期待の種類・対象領域・前提領域について、関連画素とレベルが同じで以前の結果が不支持／判定不能なら、新しい文章だけで再実行できない。遅延や確率的作用の検証は最初から`max_attempts`（1〜3）と`repeat_reason`を宣言し、`retry_of`で直前の実験を参照する。再試行時に基準や上限は変更できない。変化した前提、別の操作・対象・観測条件は新しい実験にできる。

ホスト判定後も同じ実験を提出した場合、同じツール呼び出しで訂正を繰り返さず、判定役へ一度戻す。ここでは測定済みの判定を固定し、小目標と次の介入の見直しを求める。その後も同じ条件の実験なら`experiment_redesign_stalled`で停止し、別操作へ勝手に差し替えない。再判定する古い実験には、その実験自身の前後観測を渡す。

`submit_decision`の操作以外の選択肢は `invoke / trial / evaluate / learn / stop`。これらは`purpose`を記録し、`experiment`は不要。

- `invoke`: active版の手続きを実行する。
- `trial`: candidate版を現在の実ゲームで試す。通常と同じ操作・時間予算を使う。
- `evaluate`: 固定したホスト評価を実行。未評価・不明は合格としない。
- `learn`: 受付済み経験IDを指定し、スキル作成へ移る。
- `stop`: 課題の実行を終える。

スキルの各手の後に実観測と受付を確認する。次の開始条件を満たせば、同じ手続き内ではLLMを呼ばず続行できる。効果不一致・判定不能・境界で戻る。実行受付のない変化は学習の成功証拠に使わない。

## 最初の実行形式

固定された有限の手続きで、1〜8ステップ、整数引数は最大4個。各手に `before` と `after` がある。
開始条件は、直接測れる `cell_is`。効果は `cell_changed`、`cell_is`、`color_count_delta`、`level_increased`。
各手で少なくとも一つの変化を要求する。`color_count_delta.value`は個数の増減量ではなく対象の色IDで、現在の実装はその色の個数が変わったかを確認する。

座標は整数か `$x` 等の引数参照。宣言した引数は実際に使う必要があり、余分な引数・未宣言の参照・盤面外の座標は拒否する。
開始条件や効果は画像の色IDと到達レベルから計算し、モデルの自己申告したfactを評価しない。

この最初の形式には任意コード、分岐、待機、可変長ループ、スキル同士の呼出しはない。従って、時間遅れを待って成立する作用、意味的な対象追跡を要する処理等は自動化できず、判断役の一手ごとの操作で扱う。RGBのみで色IDグリッドがない場合はセル効果をunknownにする。拡張前にこの境界で獲得と再利用を測る。

## 候補と登録

固定の方法スキルは `notebook / design-experiment / review-experiment / skill-creator`。`notebook`だけを任意ロードの一覧に置き、残りは担当する仕事の開始時にホストが読み込んで記録する。設計に判定・手続き作成の詳細Schemaを混ぜない。

開始用ビューには大目標から小目標への最大4段の経路、進行中の実験、短い直近判定、最新結果、しおり一覧を渡す。差分検査用の画素コピーは開始用ビューから除く。その他のページは6件ずつの索引から参照する。レベル／リセット境界では直前の実験を判定した後に局所目標・しおりを初期化する。過去の版は明示参照できる。

候補はゲーム版ID、説明、引数、手続き、根拠となる経験ID、実例の引数を持つ。完全な連続実行の記録に一致するseedがなければ作成できない。手書きの成功宣言では作れない。

評価ポリシー `observed-effects-v1`:

1. seedの再生照合と、開始条件を破ったホスト生成fixtureでの適用拒否。
2. 作成後の実試行が少なくとも2件、seedと異なる開始グリッド／引数で成功。同じ条件の繰り返しは件数に加算しない。
3. 失敗またはunknownの試行がない。
4. 改版時は旧版の成功記録にも一致する。
5. 他のactive版の内容と保存済み成功記録が壊れていない。

これは初期の保守的な固定基準であり、統計的な一般化保証ではない。失敗した版は成功試行を増やして失敗を隠すことができず、根拠を確認して改版する。採点器やDSL実行器の単体・結合テストは開発時のテストスイートで検証する。画像の再生から未実行操作の結果を作ることはしない。

ライブラリはIDによる明示呼出し。上記の回帰照合はモデルのスキル選択精度まで保証しない。選択の適切さ・最終課題への寄与は実走行で別途測定する。

候補は内容ハッシュで固定し、`candidate / active / suspended` をホストだけが変更する。合格した改版が登録されるまでは旧active版を保つ。採用済みスキルの実行で予測外の結果を得た場合は自動再利用を停止する。

## 永続化と再現

既定では一ゲームにつき独立したライブラリ。ログを有効にすると `<run>/skills/library.json` に仕様・根拠・評価を保存し、各版のディレクトリにSKILL.md、procedure.json、evaluation.jsonを書き出す。
`COGNITION_SKILL_LIBRARY`または評価の`--skill-library`で明示的に読み込んだactive版だけを再利用する。内容ハッシュ・評価ポリシー・証拠を再確認する。ファイルは信頼するローカル評価成果物であり、暗号署名付きの外部配布形式ではない。

`--no-learning`では作成・試行・評価を禁止し、既存active版の呼出しだけを許す。別ゲーム版では再利用しない。通常の評価で試行間の学習を暗黙共有しない。

最新の経験は128件、ライブラリは一ゲーム32版まで。候補の根拠と試行は版にコピーするため、通常履歴の退避で採用証拠が失われない。再起動後のゲーム途中からの正確な継続は対象外で、状態の二重実行を避けるためドライバの受付を記録する。

## ログと削除したもの

[評価ガイド](local-evaluation-ja.md)のログから、モデルへの実入力、判断更新、実操作、候補の根拠、試行、評価、登録を追跡できる。

削除対象は旧CognitiveTurn、ASSESS/DELIBERATE、計画DAGと旧Proposal/Interpretation、プレビューカーソル、状態別スキル選択、共通文脈A/Bの実行コード。旧API用のテストは、新しい実行・学習の挙動テストに置き換えた。通信プロトコル、公式ゲートウェイ、画像の色と座標、提出用梱包の検証は維持する。

古い設計仕様書は削除し、研究メモと評価記録は[履歴](history/README.md)へ分けた。過去のログ・評価ソーススナップショットは削除しない。

現在の契約では、旧`Decision.prediction`と`prediction_unverified`、通常判断の`action`仕事、スキル作成役の直接操作経路を廃止した。判断の目的は`purpose`、操作前の具体的予測は`experiment.expected`へ分離した。旧形式の変換・二重実装は置いていない。
