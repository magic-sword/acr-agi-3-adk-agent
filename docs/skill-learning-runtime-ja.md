> 旧実装の記録です。現行仕様は[段階別の熟考と高速実行](fast-slow-runtime-ja.md)を参照してください。

2026-09-26時点の仕様。対象と疑問の記憶は[世界記憶の設計・参考文献](object-world-memory-design-ja.md)。設計理由は[判断を限定したタスクへの設計](focused-task-refactor-design-ja.md)、スキル学習の背景は[初期設計](autonomous-skill-learning-design-ja.md)。

## 実行

ADK Workflowの制御骨格は `DECIDE → RUN → 必要時DECIDE`。モデルは一回に一つのタスクを担当し、正本の攻略ノートへの変更・分岐・実行はホストが行う。

|タスク|判断すること|
|---|---|
|`interpret_world`|画素候補から対象・関係・未解決の疑問を提案。役割や同一性は仮説として保持|
|`select_goal`|未検証の疑問IDから小目標と完了条件を選ぶ。同じ疑問の再登録は拒否|
|`assess_goal`|固定した小目標と測定事実から継続・完了・置換・保留を判断。画像や全スキルは渡さない|
|`design_experiment`|固定した小目標への一つの実験。目標の変更はできない|
|`inspect_target`|原画像から対象の矩形を求める。矩形と対象候補の実画素への命中判定はホストが行う|
|`judge_effect`|固定した意味的な予測を実際の前後画像で判定。目標の完了は決めない|
|`choose_method`|探索・既存手続き・候補試行・作成から、実際に利用可能な方法を選ぶ|
|`resolve_arguments`|選択済みスキルの整数引数を決める|
|`skill_creation`|選択済みの受付済み経験から候補手続きを作る|

各応答は`task_id`、観測ID、小目標の参照版に結び付ける。別タスク・古い観測・古い目標版への回答は実行しない。LLMには全ノートを書き換えるツールを渡さず、必要な原観測を読むツールも当該タスクに付いた参照IDに限定する。呼出しは`include_contents='none'`で、会話履歴を暗黙に追加しない。

予測は `region_changed`、`level_increased`、`semantic`。画素とレベルはホスト測定、意味は専用モデル判定。結果は`EffectFact`として判定・所見・根拠を保存し、機械測定から小目標の解釈文を生成しない。小目標の状態変更は次の`assess_goal`だけが行う。予測と実験条件は操作前に固定する。

実験設計が提案したクリックは対象確認を通す。不一致・不確実なら対象矩形と理由を設計へ戻し、ホストが勝手に座標を差し替えない。同じ観測・対象記述・操作に限り確認を再利用する。スキルの各手は既存の画素条件と実行受付をコードで検証する。

不支持の実験に対する操作・観測範囲・関連条件の変更はホストが比較する。`revision`は旧保存形式との互換用にホストが生成する値で、モデルに変更の自己申告を求めない。新しい説明や小目標名では重複検査を解除しない。実観測一つにつき回復は最大2回で、超過は`recovery_budget_exhausted`。通常の呼出し予算が先に尽きる場合もある。

遅延等の再試行は最初から`max_attempts`（1〜3）と理由を宣言し、`retry_of`で固定した実験を参照する。関連条件が変わった場合や有限再試行は同じ座標でも可能。永久的な座標禁止は行わない。

スキル作成候補は、受付があり宣言した実験効果が支持された経験から選ぶ。画面の別の場所が変わったことだけでは候補にしない。候補試行が2件以上記録された時点で、採用判定はホストが呼び出す。異なる開始条件・seedとの差・失敗の有無等の既存ゲートは維持する。選択中の手続きは各手の開始条件・効果を満たす限り、LLMを呼ばず続行できる。

既定は一観測あたり4判断・8HTTPリクエスト。初回クリックは通常4判断、画素判定後の継続も通常4判断（世界解釈を含む）。意味判定、方法選択、目標置換、差し戻しには追加の判断が必要で、既定予算内で回復できるとは限らない。上限は暗黙に増やさない。

## 最初の実行形式

固定された有限の手続きで、1〜8ステップ、整数引数は最大4個。各手に `before` と `after` がある。
開始条件は、直接測れる `cell_is`。効果は `cell_changed`、`cell_is`、`color_count_delta`、`level_increased`。
各手で少なくとも一つの変化を要求する。`color_count_delta.value`は個数の増減量ではなく対象の色IDで、現在の実装はその色の個数が変わったかを確認する。

座標は整数か `$x` 等の引数参照。宣言した引数は実際に使う必要があり、余分な引数・未宣言の参照・盤面外の座標は拒否する。
開始条件や効果は画像の色IDと到達レベルから計算し、モデルの自己申告したfactを評価しない。

この最初の形式には任意コード、分岐、待機、可変長ループ、スキル同士の呼出しはない。従って、時間遅れを待って成立する作用、意味的な対象追跡を要する処理等は自動化できず、判断役の一手ごとの操作で扱う。RGBのみで色IDグリッドがない場合はセル効果をunknownにする。拡張前にこの境界で獲得と再利用を測る。

## 候補と登録

各タスクの指示と契約は`agent/cognition/tasks.py`、入力の組立てと適用は`focused.py`に置く。旧方法スキルは本番の全タスクにロードしない。攻略ノートの人間用ビューと、LLMへの限定入力は別に記録する。レベル／リセット境界では局所目標・対象確認を失効させ、過去の版はログに保存する。

候補はゲーム版ID、説明、引数、手続き、根拠となる経験ID、実例の引数を持つ。完全な連続実行の記録に一致するseedがなければ作成できない。手書きの成功宣言では作れない。

評価ポリシー `observed-effects-v1`:

1. seedの再生照合と、開始条件を破ったホスト生成fixtureでの適用拒否。
2. 作成後の実試行が少なくとも2件、seedと異なる開始グリッド／引数で成功。同じ条件の繰り返しは件数に加算しない。
3. 失敗またはunknownの試行がない。
4. 改版時は旧版の成功記録にも一致する。
5. 他のactive版の内容と保存済み成功記録が壊れていない。

これは初期の保守的な固定基準であり、統計的な一般化保証ではない。失敗した版は成功試行を増やして失敗を隠すことができず、根拠を確認して改版する。採点器やDSL実行器の単体・結合テストは開発時のテストスイートで検証する。画像の再生から未実行操作の結果を作ることはしない。

ライブラリはIDによる明示呼出し。上記の回帰照合はモデルのスキル選択精度まで保証しない。選択の適切さ・最終課題への寄与は実走行で別途測定する。

候補は内容ハッシュで固定し、`candidate / active / suspended` をホストだけが変更する。合格した改版が登録されるまでは旧active版を保つ。採用済みスキルの実行で予測外の結果を得た場合は自動再利用を停止する。

## 永続化と再現

既定では一ゲームにつき独立したライブラリ。ログを有効にすると `<run>/skills/library.json` に仕様・根拠・評価を保存し、各版のディレクトリにSKILL.md、procedure.json、evaluation.jsonを書き出す。
`COGNITION_SKILL_LIBRARY`または評価の`--skill-library`で明示的に読み込んだactive版だけを再利用する。内容ハッシュ・評価ポリシー・証拠を再確認する。ファイルは信頼するローカル評価成果物であり、暗号署名付きの外部配布形式ではない。

`--no-learning`では作成・試行・評価を禁止し、既存active版の呼出しだけを許す。別ゲーム版では再利用しない。通常の評価で試行間の学習を暗黙共有しない。

最新の経験は128件、ライブラリは一ゲーム32版まで。候補の根拠と試行は版にコピーするため、通常履歴の退避で採用証拠が失われない。再起動後のゲーム途中からの正確な継続は対象外で、状態の二重実行を避けるためドライバの受付を記録する。

## ログと互換性

[評価ガイド](local-evaluation-ja.md)のログから、モデルへの実入力、判断更新、実操作、候補の根拠、試行、評価、登録を追跡できる。`task_opened`は実際に渡した限定入力、`plan_delta`はホスト比較、`task_rejected`は差し戻し理由と回復回数を保存する。状態図と表示は新タスクに対応し、旧ログも再生できる。

本番の`CognitiveRuntime`は新方式のみ。旧コントローラの入出力を使う既存テストは`tests/legacy_runtime_fixture.py`に隔離し、共有の実行・実験保存・過去ログ契約の回帰用に残す。テスト用コントローラは提出用ノートブックに含めない。新しい分岐自体は`tests/test_focused_tasks.py`で実ADKディスパッチを通して検証する。

実モデルでの成功率やステージクリアは自動テストとは別に扱う。比較実走の結果・残る制約は[設計書の実装記録](focused-task-refactor-design-ja.md)を参照する。
