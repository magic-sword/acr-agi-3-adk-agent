# 行動計画の現在の採用方針

更新：2026-09-29。**最終目標を小目標へ分解し、動詞＋対象の抽象操作から複数ステップの手順を作り、高速モデルが具体的な1アクションへ変換して実行する構成を維持する。** 単一操作判断だけへの置換はユーザーの意図と異なったため撤回・復元した。

## 計画と実行の分担

| 工程 | 責務 |
|---|---|
| 認識 | SAM・プログラムで対象候補を得て、対象ID・全体／部品・対応仮説を維持 |
| 状況理解 | 現在の対象・関係と最終目標の仮説 |
| 小目標生成 | 最終目標から次に達成・検証する小目標を選択 |
| 抽象操作候補 | 動詞＋対象と期待効果を提案。対応する試行事実を添える |
| 行動計画 | 目的・候補・証拠から選び、継続・終了条件を持つ手順へ具体化 |
| 高速実行 | 現在の手順と画面から1トークンで具体的な1アクションを選択 |
| 結果照合 | 検証上限・手順完了・実行の問題などの節目で計画を更新 |

クリックの座標決定は現在のマスクを使うホスト処理。カーソル調整を繰り返すモデルループは不要。高速実行の役割そのものは残す。汎用的な記憶読み出しも不要で、対象に対応する重要な試行事実をプログラムで渡す。

## 維持する条件

- 計画対象の無変化・不明と、別対象の実測変化に履歴を絞る。
- 効果不明なら小さな検証へ進める。操作不能はホスト検証で止める。
- 未操作の検証を完了扱いしない。受付・観測を実測として扱い、因果解釈と分ける。
- 同じ手順の継続時は高速側で処理し、毎操作で全計画を作り直さない。
