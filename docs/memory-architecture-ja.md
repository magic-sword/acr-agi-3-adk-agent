# 記憶の区分と記録内容の設計

作成：2026-09-30。現行の `FocusedRuntime`（memory schema 16）が、どの情報を記録し、何をモデルに渡しているかを計測した。そのうえで先行研究をもとに、記憶を区分し、残すもの・捨てるもの・要約して残すものを決める。この文書は設計と検証計画であり、攻略性能の改善を示すものではない。

関連：[対象・関係・疑問の世界記憶（旧設計）](object-world-memory-design-ja.md)、[操作履歴の絞り込み](compact-history-validation-ja.md)、[現行方針](visual-recognition-handoff-ja.md)。

## 1. 現状：入力の半分以上は同じ試行記録の繰り返し

対象は `outputs/evaluations/20260929T173558349666Z`（3ゲーム、30手・600秒）のモデル入力全件。数値は工程ごとの平均文字数で、日本語ではなくJSON文字数。トークン数はおよそ文字数÷3.5。

| 工程 | 平均入力 | 主な内訳 |
|---|---:|---|
| understand | 26,057 | 物体索引 7,504／知覚結果 7,492＋領域一覧 2,849／直前の試行 2,908 |
| backchain | 14,896 | `evidence.past_trials` 7,975（54%）／`conditional_knowledge` 2,323 |
| candidates | 29,802 | 対象ごとの `related_history` 11,939（40%）／`past_trials` 8,426（28%） |
| ground | 30,189 | 候補ごとの `related_history` 9,499（31%）／`past_trials` 8,307（28%） |
| reconcile | 22,742 | `past_trials` 7,878（35%）／`target_history` 5,581（25%） |

履歴そのものは件数上限があり、際限なく増えてはいない（試行台帳16件、入力は直近3件など）。問題は次の2点である。

1. **同じ試行を何重にも入れている。** 同じ試行カードが `evidence.past_trials`、候補ごと・対象ごとの `related_history`、reconcile の `target_history` に重複して入る。3候補が同じ物体を指すと、同じ履歴が3回入る。`conditional_knowledge` は試行カード内の `causal_interpretation` と同じ文を再掲している。最大の ground 入力（62,837文字）では、同じ試行が4〜5回登場した。
2. **1件の試行カードが重い（3,300〜5,900文字）。** 小目標の辞書全体（`purpose`、約660文字）、操作前の場面説明（`baseline`）、1手ごとの物体別観測リスト（約1,300文字／手）を毎回含む。

結果として ls20 の ground は17,807トークンになり、`--ctx-size 16384` を超えて HTTP 400 になった（2026-09-29 17:4x）。入力処理はモデル時間の約2割を占める。

## 2. 先行研究から採る原則

| 知見 | 出典 | この設計での扱い |
|---|---|---|
| 作業記憶は容量が小さく、その判断に必要な表象だけを一時的に保持する。エピソード・バッファが知覚と長期記憶を1つのまとまりへ統合する | Baddeley の作業記憶モデル | 工程ごとに、その判断に必要な**ビュー**を毎回組み立てる。ビュー自体は保存しない |
| 言語エージェントの記憶は、作業記憶と長期記憶（エピソード・意味・手続き）に分けられる | CoALA（Sumers ら 2023） | 下の4区分と、その間の書き込み・読み出しの規則として実装する |
| 速く学ぶエピソード記憶と、ゆっくり汎化する意味記憶を分ける。エピソードは後で意味記憶へ統合（固定化）される | 相補的学習システム（McClelland ら 1995） | 試行の生データはエピソード記憶に書く。照合の時点で規則へ統合し、以降の入力には統合した結果だけを渡す |
| 多数の観察を少数の上位の知見へ圧縮すると、以降の検索対象が減り、計画の一貫性が上がる | Generative Agents の reflection、ExpeL の知見抽出 | 規則カードを1つの鍵につき1件にし、追記ではなく更新する |
| 成功した行動はスキルとして保存し、再利用する | Voyager のスキルライブラリ | 既存の `supported_skills` を手続き記憶として維持する |
| 主記憶（コンテキスト）は有限なので、外部記憶との出し入れで管理する | MemGPT | 生ログはファイル（監査記録）に残し、モデルには要約と参照だけを渡す |
| 入力が長いほど、関連情報が中ほどにあるほど性能は落ちる。似た内容の妨害情報は特に悪影響が大きい | Lost in the Middle、Context Rot（Chroma 2025） | 重複を除く。ほぼ同じ文の再掲は妨害情報として扱い、削る |
| 物体の同一性は、表面の特徴よりも時空間的な連続性によって保たれる（object file） | Kahneman & Treisman の object file 理論 | 同一性はホストが追跡で管理する（既存の対象IDと同一性区間）。モデルには結論だけを渡す |
| ARC-AGI-3 の上位解法は、試した操作と結果の記録に基づいて探索する | ARC-AGI-3 Preview の上位解法、Graph-Based Exploration | 「何もしなかった操作」も規則として残し、同じ失敗の繰り返しを防ぐ |

## 3. 記憶の区分と、現行フィールドの扱い

| 区分 | 役割 | 寿命 | 現行フィールド | 扱い |
|---|---|---|---|---|
| **感覚記憶** | 今の観測の生データ | 1観測で破棄 | 画素、SAM領域一覧、`changes`、`unresolved`、クリック候補 | モデル入力は現観測の必要分だけ。記憶としては残さない（監査ログのみ） |
| **作業記憶** | この判断に必要な要素 | 1判断 | 各工程の `_context` | 毎回、下記の記憶から組み立てるビュー。重複を禁止する |
| **エピソード記憶**（短期） | この面で何をして何が測れたか | 面（レベル）の終わりまで | `trial_ledger`、`recent_trials`、`reconciliations` | 1回の手順実行につき1件。モデルには**1行の見出し**と実測の要約文だけを渡す。詳細はログに残す |
| **意味記憶：物体** | 見えている物体が何で、同一か | 面の終わりまで | `object_memory`、`understanding.targets` | 同一性はホストの追跡で管理する。モデルが付けた名前・役割の仮説は物体側に保持し、追跡が続く限り再利用する（理解の引き継ぎと同じ考え方） |
| **意味記憶：規則** | 操作と効果の関係 | ゲーム全体（面をまたぐ場合は「前の面で得た仮説」と明記） | `causal_knowledge`（追記式16件） | **鍵ごとに1件**の規則カードへ置き換える。鍵は（操作、対象の物体または外見）。ホストが計測から集計する欄と、モデルの解釈1文を持つ |
| **手続き記憶** | うまくいった手順 | ゲーム全体 | `supported_skills` | 現行どおり。確認済みの一致があるときだけ登録する |

### 捨てるもの

- 作業記憶内の重複：候補・対象ごとの履歴の複製、`past_trials` と `target_history` の二重化、解釈文の再掲。
- 試行カードの冗長な欄：小目標の辞書全体（`desired_state` の1文にする）、`baseline` の場面説明、観測ID。
- 1手ごとの物体別観測リスト：要約文 `measured_outcome` に要約した後は、モデル入力から外す（ログには残る）。
- 過去の観測の知覚結果や場面説明：現観測で追跡できている物体の情報に置き換える。

### 残すもの（統合して残す）

- **規則カード**（新設）。例：`ACTION1 × 物体e1o7`。
  - ホストが集計する欄：試行回数、変化があった回数、代表的な効果（「e1o7が上へ5」「変化なし」など）、最後に観測したステップ。
  - モデルの解釈：1文だけ。新しい照合で上書きし、支持・矛盾の件数を併記する。
  - 状態：`untested`／`no_effect_seen`／`effect_seen`／`contradicted`。すべて「観測された範囲」での状態で、一般法則とは主張しない。
- **「効果なし」の記録**も規則として残す。同じ対象・同じ操作の無駄な繰り返しを防ぐための負の知識である。
- 物体の名前・役割の仮説：物体の追跡が切れたら、「前の物体の仮説」として降格させる。

### 統合（固定化）のタイミング

1. 1手ごと：ホストが実測（`measured_outcome` と物体別の観測）から、規則カードの集計欄を更新する。モデルは関与しない。
2. 照合（reconcile）のとき：そのエピソードの評価と解釈1文で、規則カードを更新する。エピソード記憶には見出しだけを書く。
3. 面の終わり：エピソード記憶と物体の仮説を破棄する。規則カードは「前の面の仮説」へ降格させて残す。

## 4. 工程ごとの作業記憶（ビュー）

| 工程 | 渡すもの | 渡さないもの |
|---|---|---|
| understand | 現観測の物体索引と知覚結果、直前の実測の要約文、規則カードの一覧（短縮版） | 過去の試行カード |
| backchain | 場面、規則カード、エピソード見出し（最大6件）、未解決の問い | 試行カード全文 |
| candidates / ground | 目的（1文）、対象、**物体ごとに1回だけ**の事実（その物体に関係する規則カード）、スキル | 候補ごとの履歴の複製 |
| reconcile | 今回の手順の全試行（実測の詳細を含む。これが記録すべきエピソード本体）、期待した効果、関係する規則カード | 他のエピソードの全文 |
| execute_step | 現行どおり（約3.8k文字） | — |

記録済みの入力にこの変換を当てはめた試算（`outputs/evaluations/20260929T173558349666Z` の全リクエスト、文字数）：

| 工程 | 平均：現行 → 試算 | 最大：現行 → 試算 |
|---|---|---|
| understand | 23,837 → 21,371（−10%） | 33,137 → 30,295 |
| backchain | 14,493 → 5,246（−64%） | 19,503 → 6,362 |
| candidates | 28,918 → 7,705（−73%） | 50,200 → 8,727 |
| ground | 29,436 → 10,723（−64%） | 62,837 → 14,616 |
| reconcile | 22,083 → 7,046（−68%） | 31,846 → 9,413 |

この試算では、規則カードの代わりに既存の解釈文を鍵ごとに1件へ集約して代用している。understand は大半が現観測の知覚結果なので、履歴を整理してもあまり減らない（第6節）。

## 5. 検証計画

**段階1：作業記憶のビュー化と重複の除去（規則カードは既存の解釈文を鍵ごとに集約して代用）**
**段階2：ホストが集計する規則カードの新設**（負の知識と、面をまたいだ仮説の降格を含む）

各段階で、次の順に確認する。

1. **オフライン**：記録済みの観測列をランタイムに再入力し、入力文字数・トークン数と、コンテキスト長の超過件数を比べる。
2. **実モデル**：ls20・vc33・ft09 を30手・600秒で、変更前後それぞれ**2回以上**実行する。これまでは1回ずつの比較で、vc33 のレベル1到達が再現しないなど、ばらつきが大きかった。
3. **指標**
   - 速さ：工程ごとの入力トークンと秒数、1手あたりの秒数、600秒での操作数。
   - 計画が機能しているか：計画した手の割合、代替手の理由別の件数、コンテキスト長の超過件数。
   - 記憶の質：同じ対象に同じ操作をして変化0を繰り返した回数（負の知識の効果）、照合の記述が実測と矛盾した件数（`measured_outcome` との食い違い）、理解の引き継ぎ回数。
   - 成績：到達レベル、SDKスコア。
4. **合格基準**：記憶の質の指標が悪化せず、コンテキスト長の超過が0で、1手あたりの秒数が下がること。成績は回数が少ないため参考値とし、悪化の兆しがあれば段階を止めて原因を調べる。

## 5.1 検証結果（2026-09-30）

条件ごとに ls20・vc33・ft09 を2回実行した（30手・600秒、n-gram 投機あり）。集計は `scripts/compare_memory_runs.py`、表の全体は `outputs/memory-stage2-comparison.md`。値は「1回目 / 2回目」。

| 指標 | ゲーム | 変更前 | 段階1 | 段階2 |
|---|---|---|---|---|
| ground 入力トークン／回 | ls20 | 8,780 / 6,933 | 3,819 / 3,979 | 3,855 / 4,185 |
| candidates 入力トークン／回 | ls20 | 8,621 / 6,812 | 2,575 / 2,678 | 3,156 / 2,962 |
| コンテキスト長の超過 | ls20 | 2 / 0 | 0 / 0 | 0 / 0 |
| 変化0の同じ操作の繰り返し | ls20 | 0 / 0 | **9 / 10** | 0 / 0 |
| 実測は変化0なのに「動いた」と書いた照合 | ls20 | 0 / 0 | **10 / 9** | 0 / 0 |
| 同上 | ft09 | 0 / 0 | **13 / 0** | 0 / 0 |
| 操作数 | vc33 | 15 / 16 | 20 / 18 | 18 / 16 |
| 到達レベル | vc33 | 0 / 0 | 0 / 0 | 0 / **1** |

- **段階1（ビュー化と重複の除去）**：backchain・candidates・ground・reconcile の入力トークンは約50〜70%減り、1回あたりの秒数は20〜45%減った。一方で記憶の質は悪化した。規則として残したのはモデルの解釈文で、それを鍵ごとに要約して何度も読み返させたため、最初の誤った解釈（ls20：「上を押すと全体が動く」）が固定化した。実測が変化0でも「動いた」と書き、壁に当たった上移動を10回以上繰り返した。モデル自身の文を記憶として再入力すると作話が強化される、という報告と一致する。
- **段階2（ホストが集計する操作ごとの効果＋モデル由来の文の削減）**：試行回数・変化回数・連続無変化・未試行の操作を全工程の入力の先頭に置き、試行カードからモデルの評価文を外した。作話と無駄な繰り返しは0件に戻り、トークン削減はほぼ維持した。vc33 は2回目にレベル1へ到達した（SDKスコア0.684）。回数が少ないため、成績の差は参考値とする。
- 段階2の ls20 1回目では、確認済みスキルが登録された後、候補の「再利用」の誤記（別の物体で reuse、新規の候補に skill_name、文言の不一致）で出力不正が21回続き、代替手が23回になった。これはホスト側の正規化で修正した（`normalize_candidates`、単体テスト追加）。
- 修正後の再評価（`outputs/evaluations/20260930T010230968100Z`、`20260930T013243650281Z`。表は `outputs/memory-stage2fix-comparison.md`）：
  - 候補の出力不正は全ゲームで0件になった。ls20 の代替手は2 / 3（段階2は23 / 3）、計画した手は16 / 18。
  - vc33 は2回目に10手でレベル1へ到達した（SDKスコア1.75）。
  - 作話は ls20 の1件だけ、変化0の繰り返しは ls20 の2 / 0 件。
  - ft09 の代替手は10 / 5に増えた。内訳は判断時間切れが6 / 5、計画の停滞が4 / 0で、今回の修正とは関係ない。ft09 は understand の入力が長く（1回14〜16秒）、1回の計画が45秒の判断枠ぎりぎりになる。
- 変更前から続く問題：ft09 の「変化0の同じクリックの繰り返し」は、どの条件でも6〜12件あり、段階2でも減らなかった（10 / 8）。原因は未調査。

教訓：**記憶に残すのは、ホストが測った事実を主にする。モデルの解釈は、上書き式の少数の仮説に限る。** 解釈を要約して積み上げると、入力は軽くなっても誤りを固定化させる。

## 6. 未決事項

- **understand の知覚結果（1回約1.5万文字）**：物体索引（`object_index`）と領域一覧（`candidate_index`）が同じ領域を別の形で二重に列挙している。感覚記憶として必要最小限に絞れる可能性があるが、物体の認識の質に直接影響するため、段階1・2とは分けて検証する。
- **面をまたぐ知識の移し方**：物体IDは面ごとに変わる。規則カードの鍵を外見（色・形）に置き換えて移すかどうかは、段階2の結果を見て決める。旧設計と同じく、無条件には移さない。
- **状態グラフ**：画面のハッシュ→操作→結果の記録で、未訪問の操作を優先する（ARC-AGI-3 上位解法の手法）。現状は代替手の `_action_counts` が最小限の版にあたる。
