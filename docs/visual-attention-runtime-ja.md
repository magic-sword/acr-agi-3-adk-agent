# 画面から注意と操作を選ぶ実行ループ

## 目的

20260926T103959491567Z の評価では、物体解釈・課題選択・実験設計・対象確認・結果評価を
分割したため、1〜2操作に7〜10回のモデル判断を消費した。初回の物体解釈は3ゲームとも
候補の先頭6領域へ偏り、検証済みの課題だけが残ると選択不能で停止した。

本実装は通常1要求で「前の結果の解釈、今注目するもの、次の操作」を提出する。
物体一覧、物体ID、課題ID、別の対象確認や意味判定のモデル呼び出しは必要としない。
過去の意味解釈を固定したクラスとして扱わず、画像から自由に対象や関係を見直せる。

## 入出力

入力は現在画面、変化がある場合の直前画面、合法な操作、残り時間・操作数、
受付済み操作の画素差分、直近8試行、同状態で無変化だった操作、400文字以内の作業メモ。
変化のサンプルは走査順の先頭だけでなく全画面に分散する。画素差分は因果・成功の判定ではない。

出力は `AttentionDecision`。`interpretation`, `focus`, `action`, `expectation`, `notes` と
観測IDを一度に提出する。`notes` は短いモデル仮説として全置換し、事実の台帳とは区別する。
通常は1 HTTP要求、出力は最大600トークン。契約違反・同条件反復などに限り
`COGNITION_REPAIR_ATTEMPTS=1` で追加1要求を許可する。修正が不要なら追加要求はない。

## 注意の移動と反復

無変化なら別の対象・場所・操作へ注意を移すよう指示する。別の場所が変化した場合は
その場所を確認し、進展がある場合は同じ対象に留まってよい。

ホストは「同じ画面ハッシュ・ゲーム状態・レベル・合法操作」の状態で、受付済み操作が
無変化だった場合を記録する。同状態・同操作は通常1試行で尽きる。
遅延・長押し・確率的効果の仮説に限り、最初の操作前に理由と合計2〜3回を宣言できる。
操作後に理由や対象名を書き換えても、試行回数は増えない。

これは対象の永久禁止ではない。別状態では同じ座標を再調査できる。
リセット・レベル境界で短いメモと試行台帳を消去する。最近の同条件試行は128件まで保持する。

## 境界と制限

操作の選択、ドライバの送信、受付、次の観測を分けて記録する。受付不明では停止し再送しない。
同じ観測の再提出には同じ決定を返す。勝利・評価上限・時間・操作上限では追加推論せず停止し、
モデルが回答した後にも時間を確認してから操作を選ぶ。

全画面ハッシュによる反復検知は、HUDだけが変化するケースや座標を少しずらす反復を
同じ試行とは判定しない。この場合は差分・短い履歴・モデル判断に依存する。
また、単発のモデル判断でも物体の役割や進展を誤認しうる。型の検証は意味の正しさを保証しない。

本番ポリシーからスキル作成・昇格・再利用の分岐を外した。既存のノート・実行記録・
スキルライブラリの補助実装と旧方式の単体テストは残るが、注意選択に物体候補や課題を供給しない。
旧 `focused.py` と本番の段階別判断経路は廃止した。

## 検証

`tests/test_attention.py` は実ADKディスパッチと模擬HTTP応答で、1操作1要求、
無反応時の切り替え、事前宣言した反復の上限、別位置の変化、区間境界、
古い観測ID・座標の拒否、修正回数、期限、受付と重複観測を検証する。
実モデルでの速度・継続性・ゲーム進展は短い公開ゲーム評価で別途測定する。
