# 差分を強調する5方式の比較

> 調査履歴：この資料は個別実験時点の記録です。現在の採用方針・主要な検証結果・参考文献は[統合資料](visual-recognition-adopted-ja.md)を参照してください。本文中の提案は、そのまま現行方針を表すものではありません。

2026-09-27。[先行研究の調査](change-emphasis-research-20260927-ja.md)に基づく実測。

## 結果と採用判断

**今回の条件では、白混合・外枠・ぼかし・番号付き外枠による認識精度の改善を確認できなかった。**
原画像のみを含む全5方式で、実際の上移動を「変化なし」と回答した。
座標を答えない追加診断でも同じ誤りが残った。
1件の実遷移に基づく結果なので、これらの手法一般が無効とは結論しない。

白い十字に関する懸念については、**外枠方式は十字と周囲の原色を保持する**ことを画素比較で確認した。
これは表示の性質としての利点であり、今回のモデルの認識率向上とは別である。
補助表示の候補としては原画像＋外枠を残せるが、精度改善済みとして実行側へ採用する根拠は得られていない。
ゲーム実行側の認識処理は変更していない。

## 比較条件

全条件で、原画像の前後2枚と補助画像の前後2枚、合計4枚を渡した。
原画像のみの基準条件では、補助2枚も加工しない画像とした。
全画像は428×452 pixels、64×64の盤面を最近傍法で6倍表示し、同じ座標目盛りを付けた。

|補助表示|処理|白い十字への影響|
|---|---|---|
|原画像のみ|加工なし|原色を保持|
|白混合|強調範囲の外を原色20%・白80%に混合|周囲とのRGB値の差が153から31へ縮小|
|外枠|強調範囲の少し外側に2表示pixelsの赤系の枠|今回の十字と周辺画素を保持|
|背景ぼかし|強調範囲の外を半径6表示pixelsでぼかす|小さい静止図形の境界もぼける|
|番号付き外枠|外枠に少数の番号を付与|今回の十字と周辺画素を保持|

どの加工でも、強調範囲内の原色は完全に保持した。
対象外ぼかし、枠、番号はそれぞれFGVP、赤い円によるvisual prompting、SoMから着想した設計である。
各論文のモデル・学習・マスク生成を再現したものではない。

マスクは、前後で変化した画素に接する小さな単色連結領域を、前後両方から集めて作る。
上限は領域当たり256画素。実遷移では差分52画素に対し、保護する範囲は134画素になった。
全方式で同じマスクを使用し、対象の意味・役割から選択しない。
番号はこのマスクの連結領域への参照で、追跡済みの物体IDではない。
今回の2領域は移動前後を含む橙青部分の範囲と黄色い帯の範囲である。

## 入力と計測

対象は `ls20-9607627b` の保存済み1遷移。使用可能な実際の前後画像はこの1件だった。

- **forward**：実際の前後。橙青のまとまりが上へ5画素、黄色い帯が84→82画素、十字は不変。
- **reverse**：前後を入れ替えた診断。画像上では下へ5画素、帯は82→84画素。実際の逆操作を観測したものではない。
- **same_frame**：変化前を2回提示する診断。全て不変。

操作名、以前の役割仮説、差分の文字列、正解座標・変位は渡さない。
「橙青のまとまり・白い十字・黄色い帯」を外観として指定し、位置と変化を答えさせる。
したがって、対象の自律的発見を測る課題ではない。
静止対象の定量評価は白十字に絞り、上端の青い図形は今回の採点対象に含めていない。

モデルはQwen3-VL-4B-Instruct Q4_K_M、projectorはQ8_0。
前回の比較と実ファイルのSHA-256が一致。llama.cpp fingerprintは `b11118-e6ab7c1a4`。
temperature 0、seed 123、1 slot、キャッシュありで逐次実行し、方式の順序は反復ごとにシャッフルした。
入力ごとにウォームアップ1回、本計測3回。合計15ウォームアップ＋45本計測。
前処理込み20秒、回答上限750 tokensを共通にした。

採点基準と正解範囲は計測前に保存した。
前後両方の範囲のIoUを0.6以上、十字は部分的な位置特定を許して0.4以上とする。
移動は範囲・方向・変位の整合、十字は位置と不変、帯は位置と伸縮方向を判定し、
帯の正確な画素数差は別の厳しい項目として採点した。

## 主比較の結果

以下は実遷移forwardの本計測。各方式3回。時間は前処理を含む中央値。

|方式|位置と移動|位置と十字の不変|位置と帯の縮小|帯の画素数差まで正答|秒|
|---|---:|---:|---:|---:|---:|
|原画像のみ|0/3|0/3|0/3|0/3|6.48|
|白混合|0/3|0/3|0/3|0/3|6.31|
|外枠|0/3|0/3|0/3|0/3|6.28|
|背景ぼかし|0/3|0/3|0/3|0/3|6.39|
|番号付き外枠|0/3|0/3|0/3|0/3|6.44|

逆順・同一画像でも、正しい位置特定を含む採点は全方式0/3だった。
45回答全てが3対象を「不変」と回答し、前後で同じ座標を出力した。
同一画像では変化分類だけは15/15で正しいが、位置を取り違えている。
実遷移・逆順での変化見落としは30/30。単に座標の閾値が厳しいだけの失敗ではない。

例えば、十字の正解範囲 `[20,31,22,33]` に対して `[32,32,36,36]`、
橙青の正解範囲 `[34,45,38,49] → [34,40,38,44]` に対して
`[48,48,52,52] → [48,48,52,52]` などの回答があった。
対象名は質問に含めているため、それを復唱したことを認識成功とは数えない。

全45回答が形式・時間制約を満たし、機能的役割を確定した回答はなかった。
ただし役割確定を控えるよう明示した課題であり、以前の実験より役割理解が改善したとは言えない。
事前の座標・変位整合チェックでは矛盾0だったが、白混合forwardの3回答には
「不変・画素数も同じ」と説明しながら橙青の `pixel_delta=2` とする別の矛盾があった。
この点は事後の文章レビューに記録し、事前採点値は変更していない。

## 座標なしの追加診断

主比較の初期結果を見てから設計した**探索的な追加診断**。
入力の4画像は完全に同じにし、座標や画素数の出力を求めず、
「橙青が上・下などのどちらへ動いたか」「十字は橙青のどの方向か」
「十字は動いたか」「帯は短く・長くなったか」だけを尋ねた。
各方式・ケースで2回、合計30本計測と15ウォームアップ。
出力上限220 tokens、HTTPと応答解析の時間上限20秒。画像生成時間はこの追加診断の秒数には含めない。
主比較との時間差を描画方式の効果とは解釈しない。

|方式|実遷移の上移動|実遷移の帯縮小|逆順の下移動|逆順の帯伸長|
|---|---:|---:|---:|---:|
|原画像のみ|0/2|0/2|0/2|2/2|
|白混合|0/2|0/2|0/2|2/2|
|外枠|0/2|0/2|0/2|2/2|
|背景ぼかし|0/2|0/2|0/2|0/2|
|番号付き外枠|0/2|0/2|0/2|2/2|

橙青について全30回答が不変と回答し、動く20入力では全て誤答。
十字については全30回答で「不変・橙青の左」と回答した。
「左」は部分的に合っているが、8方向の正解「左上」には達していない。
主比較の位置特定失敗もあるため、これを白十字の安定した認識成功とは扱わない。
同一画像では全方式で移動・帯の変化なしを正答した。

ぼかし以外の4方式は逆順で帯の伸長を答えたが、原画像のみでも同じ結果だった。
強調表示による向上の根拠にはならない。
方向だけに簡略化しても移動を見落としており、問題が座標出力だけに限定されるとは考えにくい。
一方、4枚の対応付け、質問形式、画像の内部前処理、モデル容量等のどこが原因かは、この比較では分離していない。

## 解釈の限界と次に優先すること

反復は同じ観測を繰り返したもので、独立した多数のゲームや遷移ではない。
別ゲームや、白い物体自体が動くケースでの一般化は未検証。
全条件に原画像を残しているため、白混合単独と外枠単独での十字認識率の差も測っていない。
同一画像ではマスクが空なので、原画像・外枠・番号付き外枠の要求内容は完全に同じになる。
その条件の微小な時間差を手法差とは扱わない。

前回の高速選択比較とは画像枚数・質問・差分の文字列・役割仮説の有無が違う。
今回の表は5方式内の比較に用い、前回との数値差を強調表示だけの効果としない。

次の優先課題は、**移動という基本的な変化を画像と正しく結び付けること**。
今回だけでは有効性未検証だが、候補を次の順で検証するのが妥当と考える。

1. 原画像の前後2枚だけを同じ方向質問で比較し、補助2枚の追加による対応付けの難しさを切り分ける。
2. 原画像を残したまま、前後で同じ範囲・縮尺の局所拡大を追加する。切出し位置は画素差分から決め、正解位置からは決めない。
3. 画素から確実に測れる変位・色・画素数はホスト側の証拠として保持し、モデルには対象との対応と役割仮説を評価させる。
4. 独立した実遷移を追加してから方式を選定する。
