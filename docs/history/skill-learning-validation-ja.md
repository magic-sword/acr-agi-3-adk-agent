## 実装した範囲

判断役を一つにし、DECIDE/RUNを通して同じ課題・作業記憶・実観測を扱う。旧状態別の認識・計画出力、計画DAG、カーソル操作、13種類の旧推論スキルとその専用コード／テストを削除した。過去の研究・実験記録はhistoryへ移し、旧仕様書は削除した。

学習は二つの固定メタスキルとホスト評価で行う。LLMは実経験から有限手続きを提案し、実ゲームで試す。登録・改版・停止はホストが管理する。採用条件はseed照合、異なる開始条件での新しい成功試行2件、適用除外と回帰の確認。失敗やunknownは合格にならない。仕様と評価証拠を保存し、別走行での再利用はライブラリを明示的に固定した場合だけ許す。

初期DSLは最大8手の条件付き直列操作。任意コード、分岐、遅延効果、スキル合成、メタスキル自身の自動更新は含まない。これらは実装済みとして扱わない。

## 自動検証

実行: `docker compose run --rm --no-deps dev python -m unittest discover -s tests -v`。

**47件成功**。実ADKとスクリプト化したモデル応答を組み合わせ、候補作成→実行受付→新しい観測による効果照合→2試行→評価→登録→再利用を検証した。環境はテスト用の観測列であり、Qwenが自律的に技能を発見した証明ではない。

- 未実行・結果不明・失敗・seedの繰り返しは昇格不可。改版の回帰と内容ハッシュを確認。
- 複数手スキルは各操作後の観測を確認し、継続中の不要なLLM呼出しを省く。効果不一致なら停止して判断へ戻る。
- 不正な判断で記憶を更新しない。二重観測・別ゲーム・実行受付の不整合を検出。
- メタスキルの段階的ロード、Qwen形式のツール呼出し、HTTP予算、監査ログ、クリックの座標、公式ドライバを検証。
- 入力ライブラリの評価前固定、欠測スコアの扱い、ノートブックのソース梱包を確認。

提出用ノートブックを再生成し8セルの構文を確認。現行状態図を再生成。Markdownのローカルリンクと`git diff --check`も確認した。

## 実モデルで発見した問題と修正

短時間の実走行で、候補がないのにtrialを選ぶ、方向ボタンへクリック座標を付ける、actの操作自体を省略する失敗を確認した。利用可能な仕事・引数を現在の環境とライブラリに合わせて宣言し、実際の不正項目に応じた訂正を返すよう変更した。

仕事別の必須項目をroot oneOfで表現した試作では、モデルが共通必須項目のpredictionを省いて同じ不正出力を繰り返した。ローカル推論サーバのツール定義／生成との相互作用が疑われるが、サーバ内部までの原因特定はしていない。最終版は共通必須項目をrootに置く単純な形式に戻し、actionを明示必須（操作以外はnull）にした。モデルの仕事選択をホストで捏造する補正は行わない。

試作の失敗ログも出力ディレクトリへ残している。各runのpackage/にその時点のソースがあるため、現在の結果と混同せず比較できる。
