**識別名を付けると、変形・分離した対象を矛盾なく説明しやすくなる兆候があった。ただし、位置だけが変わる対象の認識は改善しなかった。仮の呼び名を追加する優位性も確認できなかった。**

例えば、直接比較には「元からつながっている橙青の部分が新たに結合した」という誤認があった。一方、識別名付きには「Object Dの縦の積層が横並びに変わった」「Object Dが橙と青の二つに分かれた」と説明する回答があった。ただし、呼び名付きでも「分離したが接続は変わっていない」という矛盾が残った。

## 判断

中立的な識別名は、対象を参照しながら変形・分離を説明するための候補として残せる。一方、呼び名の追加は今回の識別名だけの条件を上回らず、採用効果を主張できない。

次に優先したい切り分けは、正しい一覧があっても見落とした位置変化である。今回の命名を移動認識の解決策として実運用へ反映する根拠にはならない。結果は現在の4B量子化モデル、UI付き入力、質問、少数のケースに限られ、Qwen系列全体や命名方式一般の限界を示すものではない。

## 目的と設計

ゲームのルールを知らずに、先に静止画の対象を記述し、その記述へ識別名や仮の呼び名を付けると、前後の変化を認識しやすくなるかを比較した。正確な座標・距離は要求も採点もしていない。

| 条件 | 前後比較で与える情報 |
|---|---|
| 直接比較 | BEFOREとAFTERの2枚 |
| 記述だけ | 2枚＋QwenがBEFOREだけから作った外観一覧 |
| 識別名 | 記述だけと同じ一覧にObject A、B…を付与 |
| 識別名＋呼び名 | 同じ一覧・識別名に、静止画認識時にQwenが生成した仮称を付与 |
| 確認済み一覧＋識別名 | 2枚＋実装担当アシスタントが確認したBEFOREの外観一覧。診断用 |

比較する3条件の説明本文・順序・初期認識は、同じsceneとseedで完全に共通にした。識別名は一覧の順番から機械的に付けるが、対象の切り出しやまとまりの選択はQwenが行う。プログラムによる同方向移動のグループ化、切り抜き、差分枠、画像へのラベル重畳は使用しない。全条件で全体画面の同じ2枚を与えた。

静止画認識では、装飾筐体を除いた盤面上の色・形・接続・大まかな場所を最大8項目で列挙させた。役割名やゲームルールは与えない。名前の生成を含む同じ初期認識を共有するため、「最初に名前を考える行為そのもの」の効果は切り分けていない。

前後比較では、一覧は誤っている可能性があり、訂正・追加できること、名前は同一物体の証明ではないこと、分離・統合・対応不明を許すことを全条件共通で伝えた。単一の移動対象を選ぶ制約や、操作方向との一致を求める制約は設けていない。操作履歴も付けず、今回は視覚的な変化認識への命名の効果を切り分けた。

## 対象

実ログはls20の移動を含むstep 0→1と、変化のないstep 6→7の2組。合成は同じ開始画面からの8組で、二色ブロック移動、白い十字移動、L字への変形、縦から横への回転、二色ブロックと十字の逆方向移動、橙と青の分離、無変化、十字と二色ブロックの外観位置交換を用いた。

位置交換例は、2枚だけでは移動と置換などを確定できない場合の診断である。「変化を見つけたか」と「対応を断定せず保留できたか」を分け、通常の移動認識率に混ぜない。逆方向移動例も、同時に変化したことだけで共通の機構や因果関係があるとは採点しない。

開始画像は3種類。各3回で静止画認識9回答、10組×5条件×3回で前後比較150回答。画像なし対照3回答、warmup 2回答を別途実行した。診断用一覧の位置記述の修正に伴う追加3回答を含め、全167リクエスト。

## 採点と再現条件

変化した対象と変化の種類を見つけたことを粗い検出として記録した。その上で、例えば「分離したが位置は不変」「元から接続していた部分が新しく結合した」という明示的な矛盾・誤った変化を含む回答は、整合した認識から除いた。微細な位置誤差や方向だけの誤りは主指標から除外する理由にしていない。帯の短縮だけを答えたls20の回答を、二色ブロックの移動認識として加点していない。

回答は条件名を隠してシャッフルし、実装担当アシスタントがすべて意味レビューした。独立した人間の盲検評価ではなく、文面から条件を推測できる場合がある。3反復は独立したゲーム3個ではない。

Qwen3-VL-4B-Instruct Q4_K_M、projector Q8_0、llama.cppを使用。モデルハッシュを今回再計算して保存した。生成設定はtemperature 0.7、top_p 0.8、top_k 20、min_p 0、presence_penalty 1.5、repeat_penalty 1、seed 3407〜3409。前回と同じ公式参考設定であり、公式ベンチマークの完全再現ではない。

入力は640×820のレトロUI付き画像で、64×64盤面を512×512へ最近傍拡大した。画像中の全盤面のRGBを原グリッドと照合した。静止画認識は700 tokens、比較は512 tokens、各20秒上限。文字数や事前認識に要する時間は条件間で等しくない。

静止画の目視確認時、診断用のls20無変化例について、人手の一覧に移動前の別場面の位置表現が残っていたことを発見した。メイン回答を読む前に修正方針と3要求を保存し、その診断条件だけを別ログで再測定した。元の3回答は保存して集計から除外した。モデル生成一覧・他の条件は変更していない。

167要求すべて正常完了し、出力上限による打切り・20秒超過はなかった。静止画認識の中央値は5.08秒。比較処理のみの中央値は直接2.80秒、記述2.47秒、識別名2.43秒、識別名＋呼び名2.54秒、診断2.54秒。事前認識を毎回新規に行う場合には、その時間を加える必要があり、処理全体が高速化したという結果ではない。

比較の入力token数は直接1234、記述1322〜1387、識別名1337〜1411、識別名＋呼び名1378〜1477、診断1314〜1359。別途の静止画認識も必要なので、同一計算量の比較ではない。

この比較は2枚間でのラベルの利用であり、長期間の識別名の維持、複数段階の改名、未知ルールの獲得、実際のゲーム攻略成績を測ったものではない。
