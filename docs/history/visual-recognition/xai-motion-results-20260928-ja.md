## 実験条件

二色ブロック1画素移動、白十字1画素移動、白十字の色だけの変化、完全無変化、緑三角の新規出現の合成5例を使用した。前回実験のBEFORE物体一覧のrepeat=0を固定した。座標・移動方向・物体の役割は採点対象にしない。対象領域は診断器だけが使い、モデルの質問文には正解領域や追跡結果を与えていない。

各例に11条件を用意し、通常のllama.cpp量子化版と公式BF16版で測定した。主測定110件、ウォームアップ2件。11条件のうち2条件は独立した自由記述課題であり、元の物体一覧IDを使う課題と精度を単純合算しない。

| 条件 | 操作と目的 |
|---|---|
| base | 元画像・元の質問・元の物体一覧 |
| target_gray / target_black | 両時点の対象領域を灰色／黒で隠す |
| control_gray / control_black | 両時点の無関係な静止領域を同面積で塗る |
| ui_gray | 盤面外を一様に塗る。寸法と盤面画素を維持 |
| restore_target | AFTERの対象領域だけをBEFOREへ戻す |
| before_only / after_only | 両時点をBEFORE／AFTERに揃える |
| free_inventory / free_no_inventory | 同じ自由記述質問で、物体一覧の有無だけを変える |

注意点：今回の無関係領域は元々RGB=102なので、control_grayは画像が全く変わらない再現性対照だった。空間的な摂動の対照として有効なのはcontrol_black。各合成例で変化が対象内だけにあるため、restore_targetとbefore_onlyも同一画像になる。55動画はすべてRGBを保持するFFV1・4fps・A A B Bの4フレームで、復号後の画素一致を検証した。

通常環境はQwen3VL-4B-Instruct Q4_K_M・Q8_0 projector、公式環境は同モデルのBF16・Transformers 5.0.0・SDPA。GPUはRTX A2000 12GB。公式入力は640×832へ変換され、画像トークンは2時点×26×20。通常環境は時間方向の組み方も異なるため、内部計測を通常環境の原因と同一視しない。

## 視覚特徴には差が残っていた

各空間位置の特徴ベクトルについて `||AFTER−BEFORE|| / ((||AFTER||+||BEFORE||)/2)` を計算した。以下は対象領域との重なり面積で重み付けした平均。異なる段階間の値は表現空間が異なるので、情報量の増減として比較しない。

| 例 | パッチ埋め込み | 最終merger | 最終mergerの同面積対照 | 出力 |
|---|---:|---:|---:|---|
| 二色ブロック1画素移動 | 0.672 | 0.451 | 0.110 | unchanged（誤り） |
| 白十字1画素移動 | 0.744 | 0.422 | 0.072 | unchanged（誤り） |
| 白十字の色変化 | 0.588 | 0.433 | 0.084 | moved（誤り） |
| 無変化 | 0 | 0 | 0 | unchanged |
| 緑三角の出現 | 0.358 | 1.273 | 0.432 | appeared |

移動2例は3本すべてのDeepStack出力にも差が残った。無変化例は、パッチ埋め込み・視覚層4箇所・merger・DeepStack3箇所の全9段階で差が厳密にゼロだった。

これは「視覚特徴に前後の違いが残る」証拠であり、「同じ物体が移動したという意味表現が十分にある」証拠ではない。また、視覚エンコーダー内の情報伝播により、画素が変わらない対照位置の特徴にも差が生じる。

## 注意の強さと正誤は一致しなかった

実際の回答で対象のkindを生成する直前の位置について、言語層1・12・24・36の32ヘッドを記録した。正解のkindを強制して作った注意ではない。通常SDPAの計算結果は変更せず、そのQ/Kから対象の1クエリだけの注意を別計算した。計測あり／なしの対象位置の次トークンlogit最大差は、5例とも0だった。

以下は第24層・32ヘッド平均の一例。相対注意1は、画像トークン内で対象面積に比例して均等に重みを配った場合と同じ密度を表す。

| 例 | 対象領域の相対注意 | BEFORE / AFTERへの画像注意比 | 出力 |
|---|---:|---:|---|
| 二色ブロック1画素移動 | 0.34 | 9.4 | unchanged |
| 白十字1画素移動 | 1.84 | 5.7 | unchanged |
| 白十字の色変化 | 8.61 | 2.0 | moved |
| 無変化 | 0.29 | 10.1 | unchanged |
| 緑三角の出現 | 0.89 | 6.4 | appeared |

白十字は対象領域への注意が強くても移動を見落とした。色変化の対象への注意はさらに強いのに、変化の種類を誤った。BEFORE側への偏りも出現の正答例に見られる。したがって、注意の弱さ・時点への偏りだけでは失敗を説明できない。

盤面外の一部にも強い重みが現れたが、これは装飾の意味を重視した証拠ではない。位置に集まる注意や他層の処理も影響する。第24層だけを選んで原因を主張しないため、4層・全32ヘッドと領域集計を公開している。これは粗い画像トークンへの注意であり、元の64×64各画素への視線を復元したものではない。

## 入力への介入で分かったこと

両環境とも、色変化例のUIを隠すと `moved` から正しい `color_changed` に変わった。一方、UI除去で1画素移動を拾えるようにはならなかった。さらに出現例は無関係領域を黒くするだけで、通常環境の見落としが正答に変わった。これは文脈への感度を示す観測であり、黒マスクを一般的な改善策にする根拠にはならない。

| 対象・条件 | 通常量子化版 | 公式BF16版 |
|---|---|---|
| ブロック／十字1画素移動・base | 2例とも見落とし | 2例とも見落とし |
| 同・UI除去 | 2例とも見落とし | 2例とも見落とし |
| 色変化・base | 移動と誤認 | 移動と誤認 |
| 色変化・UI除去 | 色変化を正答 | 色変化を正答 |
| 新規出現・base | 見落とし | 出現を正答 |
| 新規出現・無関係領域を黒塗り | 出現を正答 | 出現を正答（位置記述は誤り） |
| 新規出現・AFTERだけを反復 | 変化なし | 変化なし |

色変化例は対象領域の変化を消すと、誤った移動報告も消えた。誤答でも入力の変化に反応しており、「画像と無関係に移動と答えている」状態とは異なる。

公式版の候補スコアでも、十字移動の `moved−unchanged` は元画像で−5.25、移動を消した画像で−7.75だった。画像の差に感度はあるが、どちらもunchanged側に寄ったままである。新規出現の `appeared−unchanged` は元画像で+20.19、出現を消すと−28.44へ反転した。これは入力介入による出力依存の証拠であり、注意の強さだけでは得られない情報である。

自由記述では、通常環境の一覧あり条件と公式環境の一覧あり／なし両条件で、「白十字がオレンジになった」と正しく説明しながらkindを `moved` とした。説明と分類を分けて評価する必要がある。なお自由記述プロンプトのJSON例が `moved` を使っているため、この不整合には例示への引きずられも候補として残る。

公式環境の色変化例では、無関係領域を黒くすると、十字の移動という誤認に加えて「オレンジ十字が新規出現した」と報告した。同じ対象の属性変化を別物体の出現として扱う不安定さも見られる。

## 次の比較に活かす方針

まず「前後それぞれに何が見えるか」を対象ごとに書き、その観測文から変化の種類を判断する方式を、同じ総出力予算の直接判定と比較する価値がある。自由記述で色変化を言語化できても分類を誤る事例が、この切り分けを支持する。ただし1画素移動への改善効果はまだ未測定である。

対象の局所画像を使う場合は、前後で同じ空間範囲を切り出し、移動前後を含む余白と全体画像を残す。位置合わせで移動そのものを消さない。未知ゲームでの対象対応や同方向移動をプログラムで正解として与える必要はない。今回の既知領域は診断専用であり、そのまま運用時の物体検出器が得られたわけではない。

より強い原因検証には、対象／対照の視覚特徴を置換して出力がどう変わるかを調べる追加実験が必要。今回の注意可視化だけを根拠に、特定ヘッドの増幅や削除を実装する段階ではない。

## 限界と再現

合成5例・固定した1つの物体一覧・各条件1回の診断であり、ARC-AGI全体での改善率ではない。UI除去は広範囲の画素変更なので、同面積の対象／対照マスクとは別に解釈する。対象を隠しても物体一覧は固定されるため、消した物体を「変化なし」と記述する回答は存在認識の成功として扱わない。

候補スコアは元回答の対象kind直前までの接頭辞を固定した、`unchanged`と対立候補の系列対数尤度差。先行する他物体の回答にも条件付けられ、較正済み確率ではない。色変化の対立候補は`color_changed`であり、元の誤答`moved`との直接比較ではない。
