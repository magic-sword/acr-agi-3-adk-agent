# 画素差分と追跡情報による認識の比較

> 検証履歴：測定時点の結果・提案を保存した資料です。現在の判断は[統合資料](../../visual-recognition-adopted-ja.md)、再開時の論点は[引継ぎ](../../visual-recognition-handoff-ja.md)を参照してください。前処理の採否は、後段の計画・因果推論への影響を含めて判断します。

測定日：2026-09-29。Qwen3-VL-4B-Instruct Q4_K_Mのローカル実測。

**色変化の連動は、移動対応を計算せず画素差分から抽出できた。一方、追跡情報をモデルに追加するだけでは精度は上がらなかった。** 次の構成は、プログラムが変化・移動の応答パターンから連動候補を作り、モデルは役割や次の操作を判断する形を優先する。既存追跡器の全面削除を支持する結果ではない。

### モデルを使わない連動候補の抽出：探索的な追加診断

上記の失敗を受け、同じ初期画像から始めた複数試行について、候補ごとの応答列をプログラムで比較した。全候補を処理し、正解による候補選別は行わない。新しいグループは元の候補IDを保持し、物体IDへ融合しない。

| 処理 | 使用した情報 | 同じ診断問題での結果 |
|---|---|---:|
| 色変化の連動候補 | 元候補の領域に差分があるか、試行ごとの変化／無変化の列 | **4/4** |
| 同じ移動応答の候補 | 既存追跡器による試行ごとの移動量の列 | **4/4** |

例えば二候補がともに「Aでは変化、Bでも変化、WAITでは無変化」なら、同じ応答を示したグループとして残す。前者には移動検知・Qwenとも不要。後者は一意な対応が分かった候補だけを比較し、不明な対応を移動ゼロとは扱わない。異なる初期画像の試行は自動でまとめない。

グループ化自体は8問の単回測定で中央値0.019ms。候補抽出・差分・追跡時間は別。これは**モデル結果を見た後に追加した、同じ小規模合成問題上の診断**であり、未見画面や実ゲームで8/8を再現した結果ではない。初期状態の完全一致で試行間の位置対応が分かる条件もある。共通原因や偶然の同期から、一物体や因果関係を確定しない。

### 処理時間と採用判断

87試行の準備時測定では、画素差分の生成中央値は約0.08ms。既存追跡器の更新は新規合成で2.73ms、実画面で5.15ms。前後候補一覧の生成はそれぞれ5.10ms・13.47msだった。単回の部品測定であり、追跡器内部にも色領域の抽出が含まれるため、この値を単純加算して最適化後のランタイム速度とはしない。

今回の範囲では、追跡処理の数msを削ることより、不要な画像推論やモデルに任せた数値比較を減らす方が時間への影響は大きい。ただしテキストのみの条件は精度低下があるため、画像を一律に省かない。

当面の方針は、**候補を安く保持し、差分で変化を拾い、移動量・候補参照の継続が必要な場面では既存追跡を使い、連動候補の集計はプログラムで行う**。モデルには候補の意味や次の検証操作を短く問う。連動グループの永続化・実際の質問削減・長い系列や実ゲームへの転移は未検証。本番の追跡器や状態遷移を削除する変更は今回行っていない。

## 目的と比較条件

静止画から物体全体を厳密に確定することを必須にせず、行動計画で必要な候補・変化・連動を拾う方針へ変更した。色や位置だけ分かる候補、動かない候補、物体の部品かもしれない候補も保持する。今回の問いは「同じ操作に対する応答が似ているか」であり、同一物体・役割・因果関係の確定とは区別する。

現行の移動検知は`ProposalTracker`のプログラム処理で、Qwenによる独立した移動検知呼出しはない。そのため、まず**未対応付けの画素差分だけで答えられるか、既存の候補対応・移動量を追加すると答えが改善するか**を比較した。

| 条件 | 渡す情報 |
|---|---|
| 現在画像 | AFTER画像＋現在の全候補一覧 |
| 前後画像 | BEFORE／AFTER画像＋両時点の全候補一覧 |
| 前後画像＋画素差分 | 上記＋変更した行・列・変更前後の色 |
| 前後画像＋差分＋追跡 | 上記＋既存追跡器の一意な画素対応・移動量・対応保留 |
| 差分テキストのみ（追加比較） | 前後画像＋画素差分条件から画像だけを除去。前後の候補一覧と差分は維持 |

全条件で候補の枠と色別画素数を保持。`whole`／`part`による除外、正解による候補の絞り込み、モデルが生成する候補IDは使わない。候補一覧のIDは各フレーム内の便宜的なIDであり、同一番号による時系列対応を主張しない。

差分は`[y, x開始, x終了, 変更前の色, 変更後の色]`の連続区間で、移動量・候補同士の対応・連動グループ・役割を含まない。全87試行で、BEFOREとこの差分からAFTERを完全復元できることを確認した。追跡条件は実ランタイムと同じ`ProposalTracker`を再実行し、全411リンクの前後画素と移動量を検査した。

前後画像が既に同じ観測を含むため、差分や追跡の追加は新しい観測の追加ではなく、**プログラムで計算した情報の表現による読み取り支援**の比較である。

## 問題構成と評価の範囲

- 既存合成29問：色4、移動16、パネル内部変化5、操作との対応4。過去の問題を再利用したが、今回は全条件で候補一覧も渡すため、過去の「画像のみ」の数値とは直接比較しない。
- 新規合成24問：同じ移動応答4、同じ色変化応答4、静止候補の保持4、移動／色変化／縮小／無変化の区別4、物体同一性を断定しない対照8。
- 実画面6問：ls20のブロック移動と下部バー変化2、vc33の上部ピンク線変化2、ft09の無変化2。記録に操作名がないため、因果関係や特定ボタンの効果は質問しない。

連動の合成問題は独立したA・B・WAIT試行を比較し、各試行は自身のBEFOREから開始する。色変化だけで連動する例も含める。静止候補の問題では、青い四角が残っていることと、その役割は未確定であることを答えさせる。退出・操作可能性の実証は行っていない。

主比較は59問×4条件＝236要求。画像を外す補助比較59要求は主比較の実行途中、全体採点前に固定した探索的追加であり、独立した事前登録検証ではない。temperature=0、固定seed、1トークン、許可文字の文法制約、プロンプトキャッシュ無効。各要求1回で、結果を見たプロンプト調整・再試行はしていない。

合成の候補は各画像を独立にプログラム抽出。実画面には記録済みの各フレーム独立SAM候補も加えて全条件で揃え、追跡結果を差分条件の候補生成へ混入させていない。**SAMの再実行時間は今回の所要時間に含まない**。実ランタイムの初回SAM＋通常更新を通した全体速度測定ではない。
