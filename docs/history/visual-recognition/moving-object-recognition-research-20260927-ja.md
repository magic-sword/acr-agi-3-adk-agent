# 座標を要求しない、動く物体の認識への方針修正

> 調査履歴：この資料は個別実験時点の記録です。現在の採用方針・主要な検証結果・参考文献は[統合資料](../../visual-recognition-adopted-ja.md)を参照してください。本文中の提案は、そのまま現行方針を表すものではありません。

2026-09-27。ユーザーの目的は、動く対象をカーソル・プレイヤー等の候補として理解し、
次の判断へ渡すこと。熟考側で正確な座標を出す必要はない。
本書は資料の再調査と比較設計。作成後に行った測定は
[座標を要求しない物体認識の比較結果](object-recognition-comparison-20260927-ja.md)に記録した。

## 評価する問いを変更する

前回の「指定した橙青の対象はどちらへ動いたか」では、対象名を質問側から与えていた。
その成績や、正規化座標の改善を、動く物体を自律的に見つけて理解した成績とは扱わない。
次は **「動いたものは何か、どんな見た目か、次の判断でどう扱うか」** を評価する。
座標誤差・正確な変位・画素数は主指標から外す。
差分抽出やクリック位置調整に内部座標を使うことは、熟考モデルへ座標回答を求めることとは別である。

## 直接参考になる課題

|資料・課題|測っている内容|今回への適用|
|---|---|---|
|MVBench / Moving Attribute|動いている対象の色・形・材質|対象名を教えず、移動したまとまりの外観を答えさせる|
|MVBench / Object Interaction・State Change|出来事に関わった物体、物体の状態変化|移動・伸縮・点灯等を区別し、どの物体に起きたか結び付ける|
|BLINK / Visual・Semantic・Functional Correspondence|画像間の見た目・意味・機能の対応|前後の対象を取り違えないか、表現が変わっても同じ対象を指すかを検査する|
|Qwen公式動画cookbook|動画の短い説明、出来事の文章による説明|位置の数値を含まない短い物体・出来事の記述を基本出力にする|

Moving Attributeは今回の目的に直接近い。論文ではCLEVRERの色・形・材質の質問を利用している。
ただし、これをQwenの学習データそのものが公開された証拠とは扱わない。
QwenのMVBench総合スコアから、この下位課題や本ゲームの認識率は推定できない。
[MVBench原論文](https://arxiv.org/html/2311.17005v2)

BLINKには画像間の対応付けがあり、数値座標を出す以外の検査方法を参考にできる。
同時に、一般的な画像説明だけでは細かな知覚課題を十分に解けないという分析もある。
そのため文章を流暢に生成したことを認識成功とは数えず、実画像との対応を採点する。
[BLINK著者ページ](https://zeyofu.github.io/blink/)

## 学習と公式利用例からの手掛かり

Qwen3-VLの動画学習には、時刻付きの詳しい説明と、物体・動作・人物の時空間的な対応付けが含まれる。
空間理解には対象間の関係や、何ができるかという行動に関する質問も含まれる。
このことから、外観・変化・相対関係を短文で答えさせる設計は試す価値がある。
ただし、学習に含まれる形式であることと、本ゲームで効果が出ることは同じではない。
[Qwen3-VL技術報告 §3.2.5・§3.2.7](https://arxiv.org/html/2511.21631v2)

公式動画cookbookにも、短い動画説明や出来事の文章化がある。
フレーム列とサンプリング情報を渡す処理が示され、数値座標は必須ではない。
前回確認したllama.cppの2フレーム動画経路を、その公式前処理と同一とは扱わない。
動画経路は別の検証項目として残し、まず既存の原画像2枚で物体記述課題を比較する。
[公式video_understanding.ipynb](https://github.com/QwenLM/Qwen3-VL/blob/main/cookbooks/video_understanding.ipynb)

公式fine-tuningガイドには、青い物体が動いた原因を選択肢で答えるデータ形式の例もある。
座標を伴わない物体・出来事のQAとして参考になるが、これはデータ形式の説明例であり、
その具体例で公開4Bモデルが訓練された証明ではない。追加学習を直ちに始める根拠ともしていない。
[公式fine-tuningガイド](https://github.com/QwenLM/Qwen3-VL/blob/main/qwen-vl-finetune/README.md)

## 標準設定の扱い

Qwen公式READMEのEvaluation Reproductionで示されるInstruct用設定は次のとおり。
一般的な利用例の設定、モデルファイルの既定値、学習時の設定を混同しない。

|項目|公式評価再現の設定|これまでの比較|
|---|---:|---|
|temperature|0.7|0|
|top_p|0.8|要求では未指定|
|top_k|20|要求では未指定|
|repetition_penalty|1.0|要求では未指定|
|presence_penalty|1.5|要求では未指定|
|seed|3407|123|
|出力上限|32768 tokens|課題によって16〜750等|
|推論基盤|vLLM|llama.cpp・Q4_K_M|

出典：[公式README・Evaluation Reproduction](https://github.com/QwenLM/Qwen3-VL#evaluation-reproduction)

次の診断では、temperature 0の対照と上記の生成パラメータの組を比較する。
一方、短い対象説明の回答上限は両条件で例えば256 tokensに揃える。
これは生成設定を参考にした実験であり、公式ベンチマークの完全再現ではない。
16 tokensの一文字回答用設定を、そのまま物体説明に転用しない。
標準設定への変更で認識知識が増えるとは限らず、回答の揺れや誤った断定も測定する。
追加のsampler設定とバックエンド差も記録する。
なお公式READMEにはtemperature 0を使う別の実行例もあるため、temperature 0自体を不具合とは見なさない。

## 比較すべき認識の流れ

第1段階では操作名や正解対象名を教えず、原画像の前後から対象を記述させる。
比較候補は原画像2枚と、原画像2枚＋機械的な差分領域の表示。
後者では位置指定をホストが助けているため、対象の自律発見と補助付き認識は分けて集計する。
差分画素がそのまま一つの物体とは限らないので、まとまりの組み立ても評価する。

提案する第1段階の質問：

> 前後の画像を比べ、位置が変わった物体を見つけてください。
> その物体を、色・形・一体になっている部分・おおよその場所で短く説明してください。
> 位置の変化と、長さや色だけの変化を区別してください。
> 動いたものがなければ「なし」、判別できなければ「不明」としてください。

質問文に「橙青ブロック」「白い十字」等の正解外観を入れない。
画面中央・下端・通路内等の粗い位置表現は、似た対象を区別するために使ってよい。
「中央付近の橙と青が縦につながったブロック」のような説明で対象を一意に参照できればよい。

第2段階では第1段階の記述を固定し、実際の操作履歴と原画像を追加して、
プレイヤー・カーソル・ゴール等の役割候補、そう考える根拠、次に確かめる操作を求める。
「UP直後に位置が変わったため操作対象候補」のように説明できればよい。
一回の変化から役割を確定したり、青い囲いを見ただけで出口と断定したりする必要はない。
自己生成した説明が誤っていた場合に修正できるよう、第2段階にも画像を残す。

高速側には選んだ対象の外観・粗い場所・必要なら領域参照を渡し、操作直前の位置調整を担当させる。
熟考側の数値座標を必須にしない。

## 採点を目的に合わせる

- **動いた対象の同定**：静止した十字や別の青い図形を動いたものとして取り違えない。
- **外観とまとまり**：色・形・部品の組合せが画像に合い、二色の部品を一つの対象として扱える。
- **前後の対応**：同じ対象を追い、出現・消失・変形と移動を混同しない。
- **役割仮説の有用性**：根拠付きの候補と不確かさを示し、次の操作で検証できる。
- **次の判断・高速側への引継ぎ**：説明から同じ対象を選べる。実際の行動の有効性は環境で別途確かめる。

自由記述では同義表現を許し、文字列の完全一致で採点しない。
物体を一意に特定できない「何かが動いた」は成功にしない。
診断用の選択肢問題は補助にし、それだけで自律認識成功としない。
動く対象と静止対象の色・形を入れ替えた例、不変例、画像なし対照も用意し、
決まり文句で正答していないかを確認する。

次の小規模比較は、原画像／差分補助 × temperature 0／公式評価の生成設定の4条件とする。
全条件で同じ自由記述課題と出力予算を用い、第1段階の正しさを先に確認する。
その後、役割仮説と行動への引継ぎを評価する。
以前の座標推定結果は補助診断として保存し、今回の主指標には使わない。
