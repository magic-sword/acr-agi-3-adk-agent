> 過去の実装・調査の記録です。現在の仕様・実行コマンドは[現行実装](../skill-learning-runtime-ja.md)を参照してください。旧APIと旧比較コマンドは削除済みです。

更新日: 2026-09-25（日本時間）。[現行設計](../skill-learning-runtime-ja.md)。

## 変更

Workflowを9ノードからOBSERVE・DECIDE・COMMITの3ノードへ、モデル状態をVERIFY/PLAN/PROBE/REVISEの4種類からDECIDEの1種類へ整理した。人間プレイの注釈分析にある「予測→短い試行→結果から修正」を、一つの判断内で実行する。

提出の必須項目はactionとprediction。reflectionとnotebookは任意。観測IDやrevisionの転記、部分目標の依存グラフ、実験の述語配列を初手の条件にしない。前後の画像と直前の予測を最初から渡し、各判断のHTTP往復を8回から3回へ制限した。正常時は1判断、残りの判断枠は不正提出・通信エラーの再試行に使う。

既存の合法操作・クリック座標・重複配送・順序・時間・操作数・リセット上限の検査は維持する。モデルの自由記述は仮説として扱い、ホストの検証済みFactへ昇格させない。旧型の計画・述語ユーティリティは残すが、現行Workflowからのモデル提出には使用しない。

## 測定条件

ローカルQwen3-VL-4B、公開3ゲームを各1試行。各最大12操作・1レベル・推論90秒・プロセス110秒。公式ローカルHTTPゲートウェイとSDKスコアカードを使用。Kaggleスコアの推定ではない。

```bash
docker compose run --rm --no-deps dev python scripts/benchmark_local.py \
  --games ls20,vc33,ft09 --steps 12 --levels 1 --seconds 90 --hard-seconds 110
```

初期の簡素化版では3ゲームとも12操作、全36判断が1 HTTP要求で受理された。[途中測定](../../outputs/evaluations/20260924T145407454156Z/report.md)。一方、同じ盤面での同じ操作の連続反復がls20で5件、ft09で11件あった。これを受け、最近の各操作とその直後の画面変化を対応付け、変化しない入力やクリック対象の見直しを促すようにした。過去のnotebook全文を毎回重複して入力せず、最新メモと短い試行履歴へ整理した。

3ゲームとも12操作の上限で終了し、停止理由は `budget_exhausted`、内訳は `limit_reached=actions`。時間切れや提案不能による初手付近の停止ではない。全36判断の提出が受理され、各判断1 HTTP要求、形式・操作検証エラー0。スキルのロードは今回0回であり、更新した専門手順の実ゲーム効果を測った結果ではない。

直前の最終ls20測定は、同じ上限で1操作・約99.4秒（時間切れ）、初手までのPLAN＋PROBEは約29.1秒だった。[旧測定](../../outputs/evaluations/20260924T133928514521Z/report.md)。今回、操作前の推論往復と複雑な形式検証を減らすことで、操作へ進む経路が機能することを確認した。複数の変更を合わせた各1試行であり、状態数削減だけの因果効果や安定した性能差とは断定しない。

**全ゲームでクリア0、SDKスコア0.0。攻略性能の向上は未確認。** 同じ盤面での反復は最終版にも残り、結果の入力を明示するだけでは解消していない。画面から操作対象を特定すること、無効試行後に対象や仮説を切り替えることが次の課題。操作数を伸ばしたことと有益な探索を行ったことを混同しない。

旧ユーティリティには形式的な述語検証が残るが、新しい自然言語predictionはモデルの次ターンで振り返る。意味的な正しさ・因果関係をホストが保証する方式ではない。この簡素化のトレードオフも含め、以降は長い実行時間を増やす前に、対象選択と反復の内容を観測で検証する。
