## 結論

**次の中心課題は、測定した変化・不変・不明を、行動前の予測と照合し、仮説の更新と次の検証行動までつなぐこと。** 概念は、その問いを扱える対象・対象群の暫定表現でよい。静止画からクラスを完成させることを、試行開始の条件にしない。

既に `probe → 観測 → reconcile` の経路はある。新しい大規模な推論機構を作るより、この経路で「何が分かり、何を変えて次に試すか」が正しく引き継がれるかを先に改善する。

実装順は、**試行へ到達する遷移の整合 → 予測と実測の照合 → 識別可能な検証行動 → 問いに応じた前処理・提示の変更**。記憶参照の費用は同時に測り、独立した改善として比較する。

## 2. ボトルネックの優先順位

### 最初に直す前提：計画と実行遷移の不整合

[`Grounding`](../../../agent/cognition/state.py)は「planありならexecute」と説明するが、[`validate_stage()`](../../../agent/cognition/deliberation.py)は`next != execute`で理由だけ確認して戻る。そのため、試行計画を返しても実行せず再理解に戻れる。

`plan != null ⇔ next == execute`を検証し、再理解が必要なら具体的な不足情報を要求する。矛盾を黙って実行に読み替えず、既存の修正経路で整合した出力を得る。同じ観測・問いのまま理解と計画を往復していないかも記録する。回数制限だけでは有益な試行を選べないため、停止回数の減少だけを成功としない。

### 優先1：予測を測定可能な問いにし、結果の根拠を維持する

現行の[`questions()`](../../../agent/cognition/perception.py)は`changes`から最大4問を作る。動くはずの対象が不変でも、その対象を質問するとは限らない。現行SAMの色変化は対応保留になり得るため、重要な反応が`changes`に入らず`unresolved`へ入る場合もある。

一方、[`Reconciliation`](../../../agent/cognition/state.py)の`evidence`と`causal_notes`は自由文で、[`validate_stage()`](../../../agent/cognition/deliberation.py)は主張ごとの測定根拠を検査しない。記録を消さない仕組みはあるが、矛盾した説明が次の`baseline`になることは防げない。

次の最小単位を、行動前に固定して一操作後に照合する。

| 行動前に残すもの | 行動後に残すもの |
|---|---|
| 検証する問いと仮説 | どの予測が支持・不支持・判定不能か |
| 対象候補・対象群と対応の不確実さ | 対象ごとの変化・不変・対応不明、予想外の別領域の変化 |
| 操作、成立に必要と考える条件 | 受付済み操作と対応する観測・試行ID |
| 予測する位置・色・関係の変化、観測する期間 | 判定の根拠となる測定への参照 |
| 予測が分かれる場合の比較対象 | 残った別解釈と、次に変える対象・操作・条件・観測範囲 |

ホストが照合するのは、対応が成立した候補の移動量・領域内の色変化など、測れる主張に限る。役割や自由な因果説明は仮説として保持し、形式検証だけで正しいと認定しない。根拠IDの存在確認に加え、観測時点・対象・測定値がその主張に合うかが必要。

例えば「DOWNで十字が下へ動く」を試した結果、十字の画素が不変でバーだけ変われば、「この条件・観測期間では予測した可視移動を確認できない」とする。直ちに「DOWNは無効」「バーはタイマー」「十字はプレイヤーではない」と確定しない。対象対応が不明なら、移動なしではなく判定不能にする。

### 優先2：仮説を区別する試行と、更新結果に沿う次の行動

現在も`question`、`expected_effect`、`causal_notes`、`next_question`はある。しかし、仮説ごとの異なる予測や、前の結果を受けて何を変更したかは構造化されていない。反省文を増やすだけでは同じ操作・説明を繰り返し得る。

まず重要な不確実さ一つに絞り、必要なら2〜3個の対立する説明と、それらで結果が異なる操作を考える。全ゲームの因果グラフや精密な確率推定を先に要求しない。試行後は、次の計画が「操作・対象・前提条件・観測方法の何を変えたか」を前の試行と結ぶ。条件が変わった、遅延を調べるなど根拠がある反復は許容する。

連動についても「AとBが同時に動いた」を観測として保持し、「一つの物体」「別々の物体が同じ操作に反応」「共通の仕組みで連動」は別の仮説として扱う。同じ操作の反復だけでは区別できないなら、別操作・別条件で異なる応答が出るかを検証候補にする。環境が比較を許さない場合は仮説を保留する。

この段階で必要な概念は「この条件で同じ応答をする対象群」などで十分。ただし、条件が変われば分かれる可能性と、静止している未解釈候補を残す。

### 優先3：判断に必要な情報に応じて前処理・提示を変える

現行[`HybridPerception`](../../../agent/cognition/hybrid_perception.py)は候補参照の継続／欠落を渡せる。旧分析の「候補と対象の接続がない」という状態からは改善している。ただし、前処理の`requires_review`は対象に関係なく対応保留全体で立ち、変更64遷移すべてで保留が残った検証では、常時再考の要因になる。

また、[`context_record()`](../../../agent/cognition/perception.py)は変更・保留を各先頭12件、不変を件数に縮約し、全候補索引はunderstandへ渡す。意味質問も先頭4件であり、選択基準が現在の仮説の識別力になっていない。[`_visual_parts()`](../../../agent/cognition/workflow.py)の画像省略は主に幾何の`requires_review`で決まり、意味回答の不明を直接反映しない。

後段から「対象候補／群・調べる関係・必要な時系列・判断に欠ける情報」を要求できるようにする。初めは理由を少数に分ければよい。

| 判断に欠ける情報 | 追加する処理・提示の候補 |
|---|---|
| 対象が移動したか、不変か | 対象と比較対象の前後位置・画素。変更候補がゼロでも照合する |
| 色変化で対応が切れた | 同じ周辺領域の前後画像・色差分、複数の対応仮説 |
| 離れた対象が連動したか | 操作・条件別の応答履歴、連動を破る対照例 |
| 必要対象が既存候補に見つからない | 周辺探索やSAM再実行。対象の意味が不明なだけなら再検出を反射的に使わない |
| 測定はあるが意味付けできない | 対象周辺と必要な全体文脈、焦点を絞った意味質問 |

全候補・全差分は保存し、その場の提示には対象、前提・比較対象、予想外の変化、未処理情報の有無を優先する。遠隔効果もあり得るため、注目対象の外を全部捨てない。関係ない保留は記録に残して実行を続けられるようにするが、関連性が不明な変化を無条件に無視しない。

前処理の追加要求には「どの判断が変わるか」を付け、同じ情報を再取得するだけのループと、実際に候補・根拠が増えた再観測を区別する。

### 横断課題：推論・記憶参照の費用

[`_read_memory()`](../../../agent/cognition/notebook.py)は各熟考前に任意記録をモデルで巡回し、一回最大4秒使う。まず同一観測で同じ記録を何度も選んでいないかを測る。現在の問い・対象・仮説に関連する少数の記録を自動提示し、必要な場合だけ追加参照する方式を比較候補にする。

ただし、記憶参照の削減だけで間違った照合が正しくなるわけではない。結果照合の改善と一括で変更せず、欠落する根拠と時間の両方を比較する。

## 3. 最初の実装・評価範囲

最初の変更は、**「一つの対象／対象群への一操作について、事前予測・実測・判定・次の変更を一貫させる」**ところまで。現行SAM＋画素追跡を基準とし、前処理の置換はこの評価で必要になった箇所から試す。

1. 現行SAM構成の実モデル走行をls20・vc33・ft09で保存し、初手までの時間、工程別時間、試行数、照合と次の計画を基準値にする。既存ログを上書きしない。
2. 計画と遷移の整合を直し、操作に到達できることを確認する。これを土台に、予測起点の照合と測定根拠を追加する。
3. 固定された実観測・合成診断で、下表の取りこぼしと誤確定を確認する。未実行操作の結果は保存画像から創作しない。
4. 同じモデル・初期条件・時間／操作予算で複数回比較し、仮説に沿った有益な次の試行とゲーム進展を評価する。
5. 不足情報の記録から、焦点を絞った提示、連動要約、追加画像、必要時再検出を個別に比較する。前処理の効果と後段の変更の効果を分ける。

| 回帰例 | 成功条件 |
|---|---|
| 対象は不変、バーだけ変化 | 対象の移動を観測済みと説明しない |
| 全体が無変化 | 事前予測を照合し、対象の可視不変と効果全般の否定を区別する |
| 色変化・同形物体で対応不明 | 不変・消失・同一物体を早まって確定しない |
| 重要な変化が先頭4問／12件の外 | 現在の問いに必要な証拠を取り出せる |
| 背景・部品だけの対応保留 | 重要対象が確認できる場合に、不必要な全面再考を減らせる |
| 対象外の遠隔変化・未解釈の静止物 | 必要なら計画の候補へ戻せる |
| 同時変化する複数対象 | 連動観測と因果仮説を分け、区別できる検証があれば選ぶ |
| 新しい試行で操作0回／受付不明 | 過去の試行結果を今回の成果にしない。既に成立している状態の確認とは区別する |
| 同じ試行を再提案 | 前提変化・遅延・有限回試験など再試行理由を確認できる |

評価は、必要対象の考慮漏れ、測定と矛盾する観測主張、根拠のない因果断定、保留の適切さ、次の試行で識別できた仮説、レベル進展を別々に数える。入力トークン・画像数・モデル／HTTP呼出し数・総時間・初手までの時間も記録する。「因果的に有益」は単なる操作数や説明文数で代用せず、事前に予測が分かれ、得られた結果に沿って不確実さが更新されたかを確認する。

提案を最初に記した時点では分析資料と引継ぎリンクのみを変更した。その後の実装・試走は冒頭の追記先を参照。
