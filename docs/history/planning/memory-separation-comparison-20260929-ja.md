## 比較の範囲

両条件とも前回Bの「一操作計画→既存の実行・照準→別工程の結果照合」を使う。理解・逆算・記憶選択の独立した呼出しは両方ともない。したがって、ノート読み出しステートの削除効果ではなく、各工程へ渡す情報の混在を調べる比較である。

両条件に共通の知識出力を追加した。結果照合で最大2件、対象の役割・条件付き因果関係・手順のいずれかを、対象の説明・主張・適用条件・仮説／支持／反証として保存する。根拠となる観測・試行・実操作IDはホストが付ける。新規作成と既存知識IDの改訂に対応し、改訂前も記録に残す。**保存された知識はモデルの評価であり、ホストが真実と認定したものではない。**

| 情報 | mixed（集計上A） | separated（集計上B） |
|---|---|---|
| 現在の観測 | 現在の測定と過去の測定を同じ要求に提示 | `current_observation`へまとめ、観測ごとに更新 |
| 結果照合 | 今回の結果に加えて、直近結果・直近照合・過去3試行・状況理解を提示 | 計画時に固定した`active_trial`の予測・対象説明・実操作結果を提示 |
| 今回が未実行 | 今回の結果はnullだが、別枠の過去結果が残る | 今回の結果はnull。過去の結果説明を照合入力へ入れない |
| 次の計画 | 直近3試行と前回の自由文照合 | 最後に結果が得られた1試行の操作・予測・実測・判定・次の問い |
| 継続知識 | 直近8件の抽象知識 | 同じ保存・改訂・提示規則 |
| 過去ログ | 全件保存 | 全件保存。通常の照合入力から外す |

両条件の指示文・出力schema・知識検証・画像方針・認識・実行処理は同一。指示文は両レイアウトの読み方を含む。候補IDと座標対を知識に書く形式は共通で拒否するが、自然文が十分抽象的か・因果的に正しいかまで保証する処理ではない。

これは**情報の寿命、入力の分割、過去情報の削減をまとめた比較**。単にラベルを変えた効果とは分けられない。また、共通の知識出力と指示文を追加したため、今回mixedの値を前回Bと直接比較して記憶分離の効果としない。

## 評価方法

ls20・vc33・ft09を各条件2回。1巡目mixed→separated、2巡目separated→mixed。各試走は新しいworker/session、最大12操作・1レベル・推論90秒、1観測45秒、外側110秒、修正1回。ローカルQwen3-VL-4B-Instruct Q4_K_M、temperature=0、seed=0、初回実SAM＋通常画素追跡を使用する。

受理された照合を、生の前後グリッド、現在の予測、実操作受付と照らして点検する。古い候補参照の拒否、未実行試行の結果主張、古い観測の引用、予測との不整合、知識への誤った一般化、次の試行、進展と費用を別に記録する。実装担当assistantによる非盲検の点検であり、最適行動や全概念の精度を採点するものではない。短い2反復は独立標本とはみなさない。

[固定した実行計画](../../../outputs/memory-comparison-20260929/plan.json)、[点検方針](../../../outputs/memory-comparison-20260929/review-protocol.md)、[試走別集計](../../../outputs/memory-comparison-20260929/report.md)。全12試走は同じコード・モデル・共通設定、ゲーム別に同じ初期グリッドで完了した。実要求235件のtemperature=0、熟考の指示文・出力schemaの一致（観測IDを除く）、各試走の初回SAM動作を[検証済み](../../../outputs/memory-comparison-20260929/verification.json)。

## 観測された改善と残る誤り

### 古い参照を引き継ぐ問題

ls20のmixedは両巡で、1操作後に過去観測の候補参照を再提出し、修正できず停止した。separatedは両巡とも5操作まで進んだ。現在の候補索引を明示し、過去の対象候補IDを通常の計画履歴から外す提示は、この失敗を減らす方向の結果だった。ただし、入力短縮や対象説明の変更も含むため、短期／長期という分類名だけの効果とはいえない。

vc33のseparatedは1巡目、変化した画素を1操作目の(63,0)、2操作目の(61,0)・(62,0)、3操作目の(60,0)と区別した。前回の工程比較Bにあった古い画素変化の再引用は、この走行では見られない。今回mixedは1巡目で1操作にとどまったため、これを同じ後続観測に対する正答率差としては扱わない。

### 記憶を分けても、予測を観測事実へ置き換える

separatedの2巡目ls20は、DOWNを5回実行した。各操作で変わったのは下端バーの2画素だけで、盤面上の対象は移動していない。それでも5回とも「キャラクターが下へ移動して青い四角に到達した」と支持判定した。

最初の照合には、過去の照合も抽象知識もまだない。今回の予測、今回の操作、2画素の実測だけを対応付けて渡しても、この誤りが出た。**過去記憶の混同だけでは説明できず、期待した結果を実測の代わりに説明する問題が独立して残る。** この説明を知識へ書き、以後の計画・照合が繰り返し使った。

1巡目のseparatedも、上へ動いた青・橙ブロックを「移動で新たに現れた地形・物体」と解釈した。ブロックは操作前から見えており、出現や対象への到達を実測から確定したわけではない。mixedの2巡目も、不変の白十字が移動したと誤認し、それをプレイヤーの役割知識として保存した。

### 負の知識を保存しても次の操作が変わらない

ft09のseparatedは各巡で同じ位置を5回クリックした。位置は1巡目(15,15)、2巡目(47,15)で、どちらも毎回グリッド差分0だった。各巡の受理された4照合は可視変化の予測を不支持とした。同じ知識IDへ反証を追記し、次の計画にも提示している。それでも操作と予測を繰り返した。mixedも2巡目で同じ無変化クリックを4回繰り返している。

これは「前の失敗が記憶にない」事例ではない。**記憶にある不支持の結果を、次の行動選択へ反映できていない。** 反復が妥当になる条件変更・遅延の確認なども具体化されていない。

### 抽象知識として保存する内容にも検査が必要

役割・因果・手順に分けても、`conditions`へ「クリック後に変化しなかった」という結果自体を書いたり、`y=28`のような一時的な位置を書いたりする例が出た。座標対や候補IDの形式検証は意味的な抽象化の代わりにはならない。

今回の保存規則は、知識の確定をホストが保証せず、モデルの支持・反証に出典を付けるところまで。誤った照合を根拠にした主張も入り得る。今後は、支持の根拠となる測定、適用条件、未解決の別解釈を結び、反証・訂正で更新する知識管理が必要になる。

## 次に直す箇所

記憶の分離は比較用に保持するが、この構成全体を通常設定へ採用する判断は保留する。次はステートを増減する前に、以下を同じ構成上で比較する。

1. **予測と観測を混ぜない照合。** 「どの対象のどの測定が変わる予測か」を固定し、測れる変化・不変・対応不明を先に確認する。バーだけの変化を対象移動の根拠にしない。今回のDOWN例を固定観測で比較する。
2. **知識への昇格と更新。** 実測、仮説、支持の評価を区別し、観測結果そのものを適用条件へ転記しない。根拠の弱い役割・因果関係を確定情報として再利用しない。保存した出典が主張を支持するかを確認する。
3. **反証を次の行動へ反映する。** 同じ対象・操作を繰り返すなら、条件変更・遅延・再現性確認などの理由と終了条件を明示する。不支持の知識があるのに同じ予測を無条件で再提案する例を検出する。

「長期記憶と短期記憶を分ければ解決する」までは確認できなかったが、現在の入力から不要な過去観測を外す方針には今回の根拠がある。次の中心課題は、記憶の保存先よりも、**何を事実として記憶し、どの根拠で改訂し、次の計画へどう反映するか**に移る。
