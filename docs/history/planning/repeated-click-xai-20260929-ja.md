# 同じクリックを再計画する原因と入力介入による解析

> 履歴資料。現在の採用方針は[行動計画の統合資料](../../planning-adopted-ja.md)を参照。本文の「次に検証する」は実験当時の提案であり、現在の作業予定ではない。

2026-09-29。[記憶分離比較](memory-separation-comparison-20260929-ja.md)のft09で繰り返されたクリックを調べた。今回の解析は**保存済み要求を使った入力介入**であり、内部attentionのヒートマップではない。ゲーム操作・通常ランタイムの変更は行っていない。

続く[少ない入力から追加する249要求の比較](incremental-planning-inputs-20260929-ja.md)では、質問だけから開始し、過去説明だけ・実操作の座標だけでも反復が再現した。実測を過去形の一文にすると再クリックは止まったが、追加観察を求める回答へ移った。有効な別操作やゲーム進展の改善は未確認。

## 分かったこと

**モデルは無変化を入力から読めているが、それを次の操作へ一貫して反映できていない。** 過去の対象説明と現在の画像の片方を除くだけでは、白い四角という対象説明の反復は止まらなかった。ただし、下記の補足のとおり、測定内の過去対象への対応情報などは残しており、文章と画像だけを原因と特定した実験ではない。

元の1巡目・step 2の計画は、理由欄では「前回は変化しなかった」「他の領域を試す」と説明する一方、`action.target_query`には前回と同じ「赤と青に囲まれた白い四角」を指定していた。したがって、単なる履歴の見落としとは異なる。理由欄と実行する対象の不整合が、検証を通っている。

これは提出された出力の観察であり、理由欄を内部の思考過程の忠実な説明とみなすものではない。以下の原因候補を区別する必要がある。

| 確認した事実 | 解釈・限界 |
|---|---|
| 前回の対象・操作・期待効果が複数の文章欄に残る | 過去計画を再生成する手がかりになる可能性。出現回数をattentionの強さとは扱わない |
| 知識は肯定文のclaim＋`status=contradicted`で保存 | 否定を十分反映せず肯定文を再利用する可能性。ただし否定事実へ書き換える介入だけでは反復は止まらなかった |
| 理由欄は別の対象を試すと言うのに、対象欄は同じ | 計画全体の整合不足は実際に確認。内部のどの層が原因かは未測定 |
| 無変化でも同じ操作を許す | 条件変更・遅延確認など妥当な反復もあるため、現行検証は一律禁止しない。一方、理由のない反復も通る |
| 白い四角という説明と候補IDが一致していない | 対象選択・候補対応・照準の受け渡しにも問題がある |

## 固定入力での比較

対象は`r1-ft09-separated`と`r2-ft09-separated`のstep 2におけるground要求。両方とも無変化クリックを2回実行した後、同じ対象を3回目に提案した箇所である。

モデル、指示、出力schema、temperature=0、観測ID、入力に書かれた残時間を固定し、保存した画像も復元した。基準要求は元の要求SHA-256と一致する。前後画像は同一画像で、同じ画像が2枚渡されていた。初回16要求に加え、個別の除去では別の欄に同じ対象説明が残ったため、追加4要求で同時除去を調べた。

| 介入 | 1巡目由来 | 2巡目由来 |
|---|---|---|
| 元の入力を再生（開始・終了の各2回） | 白い四角 | 白い四角 |
| 過去計画の対象説明・期待効果などを除く | 白い四角 | 白い四角 |
| 継続知識を除く | 白い四角 | 白い四角 |
| 知識を「実クリックで可視変化なし」という事実表現へ変更 | 白い四角 | 白い四角 |
| 前後画像を除く | 白い四角 | 白い四角 |
| 現在の物体測定を除く | 白い四角※ | 白い四角※ |
| 過去計画文を除き、知識を上記の事実表現へ変更 | 白い四角 | 白い四角 |
| **過去計画文と知識を両方除く**（画像・測定は残す） | 白い四角 | 白い四角 |
| **過去計画文・知識・画像を除く**（現在の測定は残す） | 中央の暗い灰色の四角 | 左上の赤い四角 |

**上表の「除く」は入力全体の除去ではない。** 全行で、指示文・出力schema・現在の問い・前回の実操作と無変化の結果を残した。現在の測定も、その除去を明示した行以外では残す。この測定には物体候補85件の座標・色・追跡ID、色名表、`target_correspondence`が含まれる。最後の行にもこれらがあり、入力が空になった条件はない。

表は**出力された対象説明**の点検であり、同じ座標をクリックしたという実行結果ではない。照準・実操作は再生していない。※測定を除いた2応答は、存在しない候補IDを生成した。代替対象への変更も、正しい対象対応や有益な行動だと確認できたわけではない。

基準再生4件は元の計画JSON全体と一致した。20応答すべてが計画schemaを満たしたが、上記2件は候補参照の存在検証を満たさない。対象の意味的な一致まではschemaで保証されない。

この2入力での介入からは、**他の入力を残した条件下で「過去の説明を残して画像を外しても白い四角」「画像を残して過去の説明を外しても白い四角」**という出力の維持が確認できる。両方を外した際に説明が変わったが、候補IDまで別の対象になったとは限らない。これは局所的な入出力依存の根拠であり、文章と画像だけが原因だという特定、各入力の内部attention値、一般的な重要度ランキングではない。

## 補足：残っていた入力と過去対象への対応情報

入力全体を再確認すると、現在の測定の中に`target_correspondence`があり、前回選んだ候補を現在の候補に対応付けていた。1巡目は`f2t55 → f3t55`、2巡目は`f2t23 → f3t23`。過去の説明文や画像を除いても、過去の注目対象を指すこの情報は残っていた。「現在の測定」という枠にも、過去の選択に由来する情報が含まれていたことになる。

追加で、この項目だけを除く8要求（2ケース×完全入力／説明・画像除去済み×対応情報あり／なし）を再生した。指示文、出力schema、候補の順序、前回のクリック座標などは同一で、差分は`target_correspondence`のみと確認した。

| 入力条件 | ケース | 対応情報ありの候補ID | 対応情報なしの候補ID | 対象説明 |
|---|---|---|---|---|
| 完全な入力 | 1巡目由来 | f3t55 | f3t23 | どちらも白い四角 |
| 完全な入力 | 2巡目由来 | f3t23 | f3t50 | どちらも白い四角 |
| 過去の説明・画像を除去 | 1巡目由来 | f3t55 | f3t57 | どちらも暗い灰色の縁がある小領域 |
| 過去の説明・画像を除去 | 2巡目由来 | f3t23 | f3t43 | 中央の赤い四角→白い縁の赤い四角 |

この追加比較では、対応情報を除くと候補IDが4組すべてで変わった。これは候補選択への影響を示唆する。一方、完全入力では白い四角という説明は維持されたので、対応情報だけが白い四角を選ばせる唯一の原因ともいえない。

除去済み基準入力は前回と同一だが、再生時に一部の説明・IDが変動した。このため、各条件1回の差を安定した因果効果や内部attentionの証明としては扱わない。説明の変化、候補IDの変化、実クリック先の変化も別の指標である。今回も実クリックは行っていない。

指示文と出力schemaにはwhiteという単語や「白い四角を選べ」という指定はなかった。説明・画像除去済みの入力では、whiteという文字列は色ID対応表の`color_names[0]`に残る。候補の色・位置・並び順、前回のクリック座標、計画を必ず一つ出す制約などの影響は、今回の対応情報除去だけでは分離できていない。

否定表現への書き換えだけでも変わらなかったため、「contradictedという語を見落としているだけ」が唯一の原因だともいえない。失敗結果を読みながら、目立つ／繰り返し説明された対象をまた選び、理由欄だけ別の探索を述べるという不整合が残る。

## 候補IDと実クリックも一致していない

1巡目の元計画は白い四角を説明しながら`f3t55`を参照していた。この候補はbbox `[20,44,25,49]`、色ID 8の赤い領域である。実際に繰り返しクリックした位置は`(15,15)`だった。

2巡目の`f3t23`もbbox `[32,32,37,37]`、色ID `[2,4,9]`で、白い四角という説明とは一致しない。今回の検証は候補IDの存在を確認するが、そのIDが説明した物体かは確認していない。クリック照準は別途`target_query`の文章から位置を選ぶため、候補IDが実クリック先を直接保証する構造でもない。

つまり「同じ操作」を調べるときは、ボタンがCLICKであることだけでなく、**対象の説明・候補ID・実クリック位置**の三つを比較する必要がある。ft09で使える操作はCLICKのみなので、別の領域を選べているかが主要な違いになる。

## XAIとして取得できたもの・未取得のもの

今回取得したのは、入力群の除去・書き換えに対する出力の変化である。現在の実行経路はllama.cpp `b11118-e6ab7c1a4`のQwen3-VL-4B Q4_K_Mで、保存要求・応答には層別／head別のattention行列や入力勾配がない。したがって、現ログから「この画素・この単語に何％の注意が向いた」という図は作れない。

内部attentionを調べるには、現在のバックエンドへ計測を追加するか、内部テンソルを取得できる実装で再現する必要がある。後者で精度・量子化・画像処理などが変わる場合、まず元の反復が再現するか確認する。可視化だけで原因とせず、入力介入との整合を確認する。[llama.cppの公式サーバー仕様](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)

attentionを説明として使う際の限界と評価方法は研究上も議論されている。ここで参照する研究はQwen3-VLそのものの検証ではなく、注意重みだけで因果的重要度を断定しないための方法上の参考である。[Jain & Wallace, 2019](https://aclanthology.org/N19-1357/)、[Wiegreffe & Pinter, 2019](https://aclanthology.org/D19-1002/)

画像のどの部分が出力に効くかをさらに調べるなら、現在のモデルを固定したまま領域別の入力介入を行い、対象選択への影響を測る方法がある。ただし複数箇所に似た白い四角があるため、対象の対応を先に明確にする必要がある。今回、領域別マスク、入力勾配、attention rollout、トークン尤度による寄与測定は行っていない。

## 次の改善候補

最初に比較すべきなのは、注意を強調する画像加工より、**前回と同じ対象・操作・条件なのかを明示し、再試行するなら何を確かめるのかを計画に結び付けること**。併せて、対象説明と候補ID・照準位置の一致を確認する。単に「繰り返すな」と強く指示するだけでは、有効な反復まで失う。

今回の介入は2つの失敗入力に限る。各変形は1回で、基準のみ開始・終了に再生した。除去により通常と異なる入力になる影響や、情報間の相互作用がある。成功率改善や特定の内部機構の因果証明とは扱わない。
