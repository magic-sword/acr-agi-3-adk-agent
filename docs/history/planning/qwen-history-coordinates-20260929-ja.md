> 履歴資料。現在の採用方針は[行動計画の統合資料](../../planning-adopted-ja.md)を参照。本文の「次に検証する」は実験当時の提案であり、現在の作業予定ではない。

2026-09-29。[入力追加比較](incremental-planning-inputs-20260929-ja.md)の後、クリック位置の伝え方を分離して検証した。主比較144要求と、目盛り・余白を除く探索的追試72要求の計216要求を完了した。通常ランタイムは変更していない。

## 公式の座標と前の説明の訂正

Qwen3-VLの技術報告は、groundingで0〜1000に正規化した座標を採用したと明記している。公式Computer Use例も表示解像度を1000×1000として指定し、出力を実画像へ変換する。Mobile例には999を基準にした変換があるので、範囲・分母・対象画像を揃える必要がある。[技術報告 §3.2.4](https://arxiv.org/html/2511.21631v1#S3.SS2.SSS4)、[Computer Use例](https://github.com/QwenLM/Qwen3-VL/blob/main/cookbooks/computer_use.ipynb)、[Mobile例](https://github.com/QwenLM/Qwen3-VL/blob/main/cookbooks/mobile_agent.ipynb)

前に提示した`(15,15)`は、公式の正規化座標ではなく、64×64ゲーム盤の0始まりのセル座標だった。しかもモデルに渡した画像には目盛り・余白がある。座標系を省略した例は不十分で、公式の履歴例をそのまま再現したものでもなかった。公式Mobile例の履歴は、実行済み操作をStep順の文章で記述する方式で、履歴に座標対を必須としてはいない。

既存の表示画像は428×452、盤面左上は画像ピクセル(32,44)、1ゲームセルは6×6画像ピクセル。ゲームセル中心を画像全体の0〜1000座標へ変換すると次になる。

| ケース | ゲーム座標 | 表示画像上の中心 | 画像全体での正規化座標 | 実際の色 |
|---|---|---|---|---|
| 1巡目の履歴 | (15,15) | (125,137) | (292,303) | 白 |
| 2巡目の履歴 | (47,15) | (317,137) | (741,303) | 灰色 |

変換は`image_x = 32 + 6*(x+0.5)`、`image_y = 44 + 6*(y+0.5)`、正規化はそれぞれ画像幅428・高さ452で割って1000倍。元セルへ逆変換して一致することを検証した。ゲーム座標を単純に64で割った値を、余白込みの画像に対する座標として使うと位置がずれる。

## 実験設計

2つの保存済み履歴は、同じft09盤面で直前まで2回無変化クリックを行ったもの。現在画像は同じで、クリック先が異なる。独立したゲーム6件ではなく、各条件2履歴×3反復で6要求とした。

履歴の形式は次の2種類。どちらも同じ目的・実操作・受付済み・変化0を含む。

- **構造化**：`last_actual_result`の中に操作、位置、受付、変化をJSONで渡す。
- **公式例に近い形式**：目的と「すでに実行した操作」を示す見出し、`Step 1: I clicked ...`の履歴文、観測結果の文を渡す。観測結果の欄は今回の拡張。

後者はMobile cookbookの履歴構成を参考にしたもので、公式スタックの完全再現ではない。比較中のsystem指示と出力schemaはタスクごとに固定した。公式例の出力Thought/Action/XMLや、モデルサイズ、画像前処理、全サンプリング設定をまとめて変更していない。使用モデルは従来どおりQwen3-VL-4B-Instruct Q4_K_M、temperature=0。

位置の伝え方は6種類。

| 条件 | 表現 |
|---|---|
| bare | `(15,15)`など。座標系を明示しない対照 |
| grid | ゲームの0始まり64×64座標と、表示画像への対応を明記 |
| normalized | 余白込みの画像全体の0〜1000座標と明記 |
| marker | 数値を渡さず、直前クリックのセルを黄色の輪郭で示す |
| normalized_marker | 正規化座標と輪郭の併用 |
| language | 盤面内の配置と中央の小領域内の部分を自然言語で示す。答えの色名は含めない |

自然言語は実験者が作成した位置説明で、対象範囲が実クリックを含み、その範囲内の画素が同色であることをデータで検証した。自動生成された説明の精度は測っていない。輪郭画像は記録された数値グリッドから決定的に描画し、クリックされた6×6表示セル内のRGBを一切変えない。輪郭は過去位置であり次のクリック先の指示ではないと明記した。

各入力に対して、独立した2種類の質問を行う。

1. **位置理解**：前回クリックした領域（左上／右上など）、実画素の色、変化の有無。元グリッドから採点できる。
2. **次行動**：次のクリックを画像全体の0〜1000座標で返すか、情報不足を返す。盤面内の座標か、前回と同じセル／中央の小領域かを測る。別の座標を出しただけでは正解にしない。

2形式×6表現×2履歴×3反復×2質問で144要求。要求は毎回独立し、位置理解への回答を計画への入力へ渡さない。旧計画、長期知識、候補一覧も含めない。

## 主比較の結果

144/144要求完了。保存入力の再構成一致、schema違反0、通信・解析エラー0、打ち切り0。実測の「変化なし」は位置理解の72/72応答で正答した。

### 位置理解

各セルは「領域の正答数／画素色の正答数」。分母は各6要求。

| 位置表現 | 構造化 | 公式例に近い形式 |
|---|---|---|
| 単位なし | 3/6・3/6 | 3/6・3/6 |
| ゲーム座標明示 | 3/6・3/6 | 3/6・3/6 |
| 正規化座標 | 3/6・3/6 | 3/6・3/6 |
| 輪郭のみ | 3/6・3/6 | 3/6・0/6 |
| 正規化＋輪郭 | 3/6・3/6 | 5/6・3/6 |
| 自然言語 | 6/6・3/6 | 6/6・3/6 |

自然言語は左右の領域を正しく伝えたが、位置そのものを文章で明示しているため、この数字を純粋な視覚認識能力とは扱わない。灰色のクリック先を白と答える誤りは残った。公式形式＋輪郭のみでは、1巡目のゲーム色を注釈の黄色と答えた3件もあった。輪郭を見せれば対象の色まで正確に分かる、とはいえない。

各列の分母は6要求。盤面内であっても、有効なゲーム操作とは限らない。

単位なし・ゲーム座標の一部では、0〜1000で返すべき出力に(15,15)、(47,15)などをそのまま出した。輪郭だけの条件でも(24,24)など画像の目盛りに似た値を返す例がある。規定の出力座標系で変換すると余白上になるため、盤面外として扱い、ゲーム座標へ都合よく読み替えたり境界へ丸めたりしていない。

正規化すると座標としては有効になったが、以前の正規化座標をそのまま再提案する例が増えた。**位置の符号化と、失敗を踏まえた次行動の更新は別問題**である。公式に近い形式で反復が減る条件も、主に情報不足へ移った結果だった。

この直接座標出力は今回の比較用であり、通常ランタイムの別工程のカーソル照準とは異なる。今回の盤面外率を、既存カーソル方式の実操作の誤り率と読み替えてはいけない。

## オフラインでの実操作

主比較で盤面内だった27提案は、履歴と座標で重複をまとめると5種類だった。各種類についてseed=0で環境を再作成し、記録された前2操作を実行した後、全4096セルが保存盤面と一致することを確認してから1手だけ実行した。5/5種類が可視変化0、レベル進展0だった。

追試の盤面内30提案も同様に5種類へまとめて再生し、5/5種類が可視変化0、レベル進展0だった。両比較を通じて57件の有効座標提案を10回の個別復元で検証した。同一の履歴・座標が両比較に2種類重複するため、全体の異なる組は8種類である。盤面外や情報不足の応答は実操作しなかった。

結果はモデルの入力に戻していない。非公開ルールや環境実装を読み取って採点したものではない。これは一手の再生であり、複数手を必要とする操作の将来の有用性までは否定しない。

## 判断と次の改善候補

**座標系を省略できないという指摘は妥当で、前の例には明示・変換が不足していた。一方、この2履歴では、公式に近い履歴形式だけで実用上の精度が上がったとは確認できなかった。** 表示から目盛り・余白を除くと、一部条件の出力座標は改善したが、ゲーム上の進展にはつながらなかった。以前の反復の原因が座標系の曖昧さだけだったと特定したものではない。

課題は少なくとも三つに分かれる。

1. **座標の契約**：ゲームセル、表示画像、正規化座標をホストが変換する。入力と出力のどちらの座標かも区別する。説明文の中でモデルに算術変換させることを前提にしない。
2. **クリックした対象の照合**：今回の右上の実クリックは灰色だった。ホストが持つ実画素色・候補包含関係とモデルの対象説明を照合し、必要なら周辺拡大を追加する。画像の印は補助情報であり、モデルが印の色や位置を取り違える場合を評価する。
3. **失敗後の更新**：無変化の事実を正答しても同じ座標を選べてしまう。再試行なら前回と異なる条件・待機の必要性・検証目的を実行する操作へ結び付ける。違いのない再試行と情報不足への停滞を両方測る。

全ステートを削ることや、印を常時追加することはこの結果からは採用しない。次の比較もモデル・工程を固定し、座標契約とクリック対象の照合を整えた上で、失敗履歴の提示が次の有効な操作へつながるかを測る。
