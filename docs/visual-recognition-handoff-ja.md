# 認識・行動実行の引き継ぎ

更新：2026-09-29。このページを再開時の入口とする。実装の正本はコード、現在の方針はこのページと[行動計画](planning-adopted-ja.md)。過去の設計・検証は `docs/history/` と各検証資料に分ける。

## 現在の構成

```text
初回／レベル境界のSAM → 通常の画素追跡 → 対象ID・全体／部品の仮説
    → 現在画像・対象索引・直近4試行
    → モデル1回：直前結果の解釈＋次の1操作＋検証する疑問・期待効果
    → ホスト検証・マスク内座標 → 実操作 → 受付＋次の観測
```

通常経路は `SimpleRuntime` のみ。理解、逆算、小目標、候補生成、具体化、高速モード、カーソル調整、独立した結果照合への往復はない。次の1操作を選ぶ同じ要求で前回の結果を解釈する。出力契約違反だけは最大1回修正する。

ユーザーの優先事項は制限時間内に実観測を増やすこと。未知の効果を理由に再確認を繰り返さない。操作可能なら小さく試すが、操作不能・受付不明・終了・期限はホストで止める。1回の観測を普遍的な法則に昇格させない。

## 今回までに実装したこと

1. **領域を対象仮説へまとめる。** SAMマスクと元の画素断片を残し、領域・接触集合・共通運動・全体／部品の関係を表現する。IDと同一性区間を保持し、追跡切れ・分裂・合体を確定同一性にしない。[対象仮説の詳細](object-hypotheses-runtime-ja.md)。
2. **再確認ループを調査。** 操作前から成立する終了条件で検証完了し、未実行のまま結果照合へ戻っていた。未操作の完了を禁止し、効果不明と実行不能を区別したが、多段判断と照準調整の時間負担が残った。これらの旧制御実装は今回削除済み。[経緯](history/runtime/probe-completion-guard-validation-ja.md)、[次の検証](history/runtime/probe-execution-validation-ja.md)。
3. **通常経路を単純化。** 1操作1モデル判断へ統合。クリックは対象IDを選び、現在マスクの重心に最も近いマスク内画素をホストが選ぶ。穴のあるマスクでも穴をクリックしない。[単純化の検証](simple-workflow-validation-ja.md)。
4. **履歴を重要な観測に絞る。** 計画対象の変化・無変化・不明と、別対象の実測変化だけを保存。無関係な無変化、繰り返しの観測ID・説明、履歴マスクを入力に積み上げない。[履歴軽量化の検証](compact-history-validation-ja.md)。
5. **旧実装を削除。** 旧計画・比較ランタイム、ノート巡回、1トークン実行、照準調整、候補生成器注入を廃止。共通処理と現行テストへ整理し、遷移図・ノートブック同梱対象も更新。[削除一覧](history/runtime/retired-implementation-ja.md)。

## 現在の履歴と保証範囲

- 最大16試行を保持し、直近4試行をモデルに提示する。レベル・リセット境界で消去する。
- 計画対象のID・当時の同一性区間・位置・色、操作、受付、期待効果、測定結果、モデルの条件付き解釈を区別する。
- 対象が無変化なら0、対象の測定がなければ `unmeasured`／`null`。無変化と未測定を混同しない。
- 別対象は画素変化または移動のあるものだけ記録。画面全体の変化数も保持するが、対象への因果的効果とはしない。
- マスク内への命中はゲームの有効な作動点への命中や物理的同一性を保証しない。
- 長期の法則・スキル学習は現行経路にない。対象別履歴検索・統合の研究用関数は認識ベンチマークで検証するが、通常入力は直近4試行である。

## 確認した結果

同じvc33・SAM CPU・操作上限4回の短い試走。実モデルの選択・生成文は同一ではなく、速度比を一般化しない。クリアはいずれも0。

| 状態 | 入力トークン（4手目） | モデル判断4回の合計 | 初回SAM込み総時間 |
|---|---:|---:|---:|
| 単純化後・履歴軽量化前 | 12,763 | 31.4秒 | 68.9秒 |
| 履歴軽量化後 | 3,311 | 17.1秒 | 55.8秒 |

履歴軽量化前の同一履歴を変換した比較では、4手目の履歴が25,743文字から3,252文字へ約87%減。全対象の無変化を毎試行20〜22件ずつ蓄積していたことが主な増加要因だった。

CPU SAMは初回約37秒。通常観測ごとの負担ではない。GPU版の速度比較は未実施。モデルサーバーはGPU利用構成だが、直近のNVML確認が失敗しており、GPU使用状態を実測確認したとは言わない。

削除前は297テスト成功。旧機能専用80テストを削除し、現行経路に4テストを追加した削除後は221テスト成功。単に旧テストの失敗を無視したわけではない。最終清掃後のログは `outputs/runtime-cleanup-20260929/`。

整理後の実モデル試走は54.4秒で4操作・モデル判断4回、操作上限で終了（クリア0）。89フレームのキャッシュ済みSAM再生では対象回収392/397で、整理前と回収数・対応・ID切替の測定値は一致した。過去マスクの再生でありGPU性能の測定ではない。テスト、レポート、比較結果はそれぞれ `tests.log`、`runtime/report.md`、`cleanup-checks.json` に保存した。提出ノートブックも再生成済みで、提出・アップロードはしていない。

## 次に扱う課題

- 同じ対象の反復と、変化していない対象を操作した結果の過剰な因果解釈は残る。操作数だけで法則学習の改善と判定しない。
- 小型モデルの選択の偏り、対象対応の不確かさ、グループの誤統合は未解決。長い説明・全履歴の再投入・段階的再確認ループを安易に戻さない。
- 速度はSAM初期化、入力処理、出力生成を分けて測る。SAMのGPU実測と、履歴をさらに短くする効果は別々に比較する。
- 複数ゲーム・長い試走での性能は未確認。今回の4操作試走を攻略性能の証拠にしない。
