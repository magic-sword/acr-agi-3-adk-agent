# 直前操作の発光・クリック位置表示の比較（2026-09-27）

> 調査履歴：この資料は個別実験時点の記録です。現在の採用方針・主要な検証結果・参考文献は[統合資料](visual-recognition-adopted-ja.md)を参照してください。本文中の提案は、そのまま現行方針を表すものではありません。

今回の Qwen3-VL-4B-Instruct Q4_K_M では、直前操作をボタンの発光とクリック位置のリングで表示しても、動いた物体の認識改善は確認できなかった。ボタン名を読む単独課題では UP / CLICK をそれぞれ正答したが、前後画像を比較する課題では移動対象を見落とした。

## 比較結果

全条件に同じレトロゲーム風 UI を付け、操作履歴の与え方だけを比較した。正解数の分母は、同じケースを異なる seed で3回ずつ実行した回答数であり、独立したゲーム数ではない。

| 評価対象 | 操作履歴なし | 文字による操作履歴 | ボタン発光＋クリック位置 |
|---|---:|---:|---:|
| 動いた物体と移動を認識：5組×3回 | 0/15 | 0/15 | 0/15 |
| ls20 の黄色い帯の短縮：1組×3回、副指標 | 3/3 | 3/3 | 3/3 |
| vc33 のクリック後、離れた上端の帯が変化：1組×3回 | 0/3 | 0/3 | 0/3 |
| 実際に無変化の画像を無変化と回答：3組×3回 | 9/9 | 9/9 | 9/9 |
| 推論を含むリクエスト所要時間の中央値 | 2.96秒 | 2.90秒 | 2.85秒 |

ls20 では、全9回答が黄色い帯の短縮を認識した一方、橙と青がつながったブロックの移動は否定した。帯の認識は操作履歴なしでも同じなので、発光表示による改善とは言えない。「ヘルスが減った」「ダメージを受けた」などの説明もあったが、帯の意味や原因を確認した結果ではない。

無変化は全条件で正答したが、変化のある画像もほぼ無変化と答えている。誤検出がないことだけで、操作と画面変化を正しく対応付けられたとは評価しない。

補助診断として、発光画像1枚からボタン名だけを答える課題を2回実行し、UP と CLICK を各1回正答した。これは表示が全く読めないわけではないという小さな確認に留まる。変化認識の本課題では、発光条件の27回答中4回答に CLICK を SELECT と呼ぶ誤りもあった。

画像を与えず操作情報だけを渡す対照6回答では、画像不足を適切に留保した回答は0/6だった。「変化しなかった」と断定する傾向があり、移動を見落とす今回の結果を解釈する上で注意が必要である。

## 表示と条件

[比較画像一覧](../outputs/action-cue-20260927/gallery.html)で、各ケースの BEFORE、AFTER、無印の補助画像、操作を強調した補助画像を確認できる。

- `no_history`：操作履歴なし。
- `text_history`：UP、または CLICK とクリック位置を文字で付与。
- `visual_history`：押したボタンに水色の発光枠を付け、クリック時は入力位置にも中空リングを付与。

各条件とも640×820の画像を3枚与えた。1枚目と2枚目は元の BEFORE / AFTER、3枚目は BEFORE に操作履歴を表示する補助画像である。元の2枚は全条件で同一とし、3枚目は履歴なし・文字条件では強調なし、発光条件だけ強調ありにした。クリックリングは補助画像の一部に重なるが、クリック中心の色と元の2枚は保持した。

元の64×64盤面を512×512に最近傍拡大し、色を維持した。ゲーム名は汎用の GAME とし、筐体の LEVEL 1/7 は全条件共通の装飾で、実際のレベル情報ではない。今回、グリッド線は付けていない。

表示は静止画上の発光表現であり、点滅アニメーションや動画ではない。また、AFTER 自体に重ねる方式は試していない。

文字条件のクリック座標は入力履歴を伝えるためだけに使用した。モデルの出力には数値座標・正確な距離を要求せず、採点にも使用していない。

## ケースと正解

| ケース | データ | 操作と目視・グリッド差分で確認した変化 |
|---|---|---|
| `ls20_up` | 実ログ、step 0→1 | UP の後、橙・青の連結ブロックが上へ移動。黄色い帯も短縮 |
| `ls20_blocked` | 実ログ、step 6→7 | UP の後、盤面は完全一致 |

| `ft09_click_static` | 実ログ、step 0→1 | 中央クリック後、盤面は完全一致 |
| `synthetic_up_opposite` | 合成 | UP と提示するが、連結ブロックは下へ移動 |
| `synthetic_up_cross` | 合成 | UP と提示するが、白い十字は右へ移動 |
| `synthetic_click_target` | 合成 | 連結ブロック上をクリックと提示し、そのブロックが上へ移動 |
| `synthetic_click_other` | 合成 | 静止した連結ブロック上をクリックと提示するが、白い十字が右へ移動 |
| `synthetic_click_static` | 合成 | クリックと提示するが、盤面は完全一致 |

実ログは `outputs/context-comparisons/20260925T064149191789Z` の `r1-ls20-shared_brief`、`r1-vc33-baseline`、`r1-ft09-shared_brief` を使用した。操作 dispatch の observation_id と操作応答の next_step を観測ログに照合した。合成5組は実際のゲーム操作結果ではなく、入力方向やクリック対象からの決めつけを検出するための対照である。

主指標は「変化した対象を色・形・つながりで特定し、移動などの変化の種類を答える」こと。正確な座標、距離、プレイヤーなどの役割名は不要とした。方向は副診断であり、移動対象を正しく特定したのに方向だけ間違えた回答を主指標から除外する設計ではない。今回は移動を認識した回答自体がなかった。

## 解釈と次の判断

今回の範囲では、操作履歴の視覚表示を認識改善の根拠として採用する結果にはならなかった。操作名を読めることと、複数画像から変化した物体を対応付けられることの間に課題が残る。

前回のレトロ UI 比較には物体の説明が変わる兆候があったが、移動対象の認識向上は確認できていなかった。今回の黄色い帯の認識率を前回と比べて改善とすることもできない。今回は移動だけでなく長さ・色などの変化も尋ね、画像枚数も変えているためである。

実例は3ゲーム4組、合成5組に限られる。vc33 の変化は元グリッドの1ピクセルと小さい。別サイズのモデル、異なる入力構成、動画、発光とクリックリングそれぞれ単独の効果は未検証である。

次に検証するなら、操作表示の装飾を増やすより、既存の差分抽出から周辺を含む同じ範囲の前後画像を作り、「変化したまとまりの色・形・つながり」を答える課題に絞る候補が考えられる。その際も全体画面を残し、クリックした対象が動いたという推測と、画像で確認できる変化を分けて測る必要がある。これは今回実証された改善策ではなく、次の検証候補である。
