# 最新ステートマシンを確認する

[観測ノートブック](../notebooks/agent_observatory.ipynb)を上から実行すると、**ログがなくても最新実装の全体グラフ**を表示する。

## ウィジェットが表示されない場合

`Error displaying widget: model not found` は、保存済み出力が参照するウィジェットIDを現在の表示環境で復元できないときに発生する。ここでの「model」はLLMではなく、操作画面のウィジェットを指す。

カーネル再起動・再接続後は、JupyterLabの **Run → Run All Cells（すべてのセルを実行）** で画面を作り直す。改善しなければ **Kernel → Restart Kernel and Run All Cells** を実行する。このノートブックではゲームの再実行は行わない。リポジトリには実行出力を消した状態で保存し、過去のウィジェットIDを持ち越さない。

## 全体図

実行側の `agent/cognition/machine.py` にステートと条件付き遷移を定義し、実行時のルーティングと表示で共有する。観測、熟考、スキル選択、手順実行、8による熟考への復帰、7による段階移行、操作待ち、終了を表示する。ADKのDECIDE/RUNはこれらを呼び出す制御骨格であり、タスクの全体図とは区別する。

- 青いステートはLLM判断、緑はホスト処理、赤は終了。
- 橙の破線は差し戻し。グラフ上部のチェックでスキル・差し戻し・停止の経路を薄くし、通常経路を追える。
- 矢印の番号は下の遷移条件一覧に対応する。矢印にカーソルを置いても条件を確認できる。
- 時間・操作予算・受付不明など、全体に適用する停止条件は赤い欄にまとめる。
- 各タスクの指示と出力契約は下部で開ける。

コードの編集後は**最新の構造を再読込**で反映する。ログ再生時にもソースの変更を確認する。ソースはASTで読むため、表示のためにモデルやエージェントを起動しない。TASKSとステート宣言が一致しない場合はエラーになり、古い図へフォールバックしない。

## 実行記録を分析する

1. 最新実装で `make benchmark` を実行し、`outputs/evaluations/<評価ID>`に記録を作る。
2. ノートブックで**評価ID → ゲーム → 読み込む**を選ぶ。
3. **問題箇所**から差し戻し・出力エラー・停止へ移動する。
4. 同じ時点の入力、モデル応答、ホスト判定、前後画面、ノートを照合する。「計画・スキルを読む」で、目標、逆算計画、因果メモ、実行段階、選択肢と熟考への復帰履歴を確認できる。

「表示時点までの実行経路」には未来の判断を混ぜない。実行時のモデル名と一観測の判断時間と計画出力の修正回数も表示する。画面の赤丸は選択したクリック位置であり、成功した位置という意味ではない。

最新形式はmanifestの`observatory_schema: 3`を持つ。旧ログの変換・過去構造との切り替えは廃止した。読めない記録はエラーとする。旧評価ログ41件を削除済みで、削除一覧は`outputs/state-graph-cleanup.json`。

グラフ自体は実行記録が空でも利用できる。ノートブックは保存ログの読取り専用で、評価やモデルを自動実行しない。

熟考は状況理解・前提条件の逆算・実行手順への具体化・結果照合の4状態。計画パネルには目標の依存関係、完了候補と確認状態、手順の起動ID、照合の根拠を表示する。
