# JupyterLabでゲームとエージェントを見る

[観測用ノートブック](../notebooks/agent_observatory.ipynb)をJupyterLabで開き、上から実行する。対象は、今回追加した状態ログを含む新しい走行。実行中のライブ表示と、保存後の再生に同じログを使う。既定では保存済みログの表示だけを行う。提出用ノートブックとは別ファイルで、ゲーム攻略用ソースを編集する必要はない。

## 準備と保存済みログの再生

`make lab`で起動する既存のJupyterLab（SSH転送先 `localhost:8889`）を使う。環境に含まれるipywidgetsで表示する。追加の外部サービスや配信サーバは不要。

1. `LOG_ROOT`に評価ディレクトリまたはcognitionディレクトリを指定する。既定の`outputs/evaluations`なら状態ログを記録した走行から選べる。最初はライブ実行で記録を作る。
2. 「走行」でゲームと実行IDを選ぶ。
3. ▶で再生、スライダーで任意イベントへ移動。「前／次の操作」は異なるstepへ移動する。
4. 入力・出力などは下のタブで読む。「記録済みアニメーション」は、その時点で取得済みの遷移の途中フレームを再生する。

イベント単位なので、一操作の途中のモデル要求、スキルロード、ツール失敗にも止まれる。表示位置より未来の受付・画面・状態出力は参照しない。状態は入場・退出の実記録から表示する。

## ライブ実行

ターミナルで`make benchmark-prepare`、`make model-up`を済ませる。ノートブックの`RUN_LIVE=True`を設定し、ゲームID・操作数・時間上限を指定して起動セルを実行する。カーネルを塞がず既存の`benchmark_local.py`を別プロセスで実行する。

約1秒ごとに追記を読み込み、モデルが処理中でも画面と現在状態を表示する。初期準備中は画面の到着を待つ。「起動・終了ログ」でモデル接続失敗などを確認できる。新しい出力は`outputs/evaluations/<日時>-monitor`、プロセスログは`outputs/monitor-process/`に保存する。

「最新を追従」をオフにするかスライダーを動かすと、エージェントを動かしたまま過去のイベントを調べられる。再びオンにすると最新へ戻る。

「実行を停止」はこのビューアが起動したプロセスとそのワーカーだけを停止する。他のターミナルで始めた評価を監視している場合には押せない。強制停止では未完了の状態・不完全なJSONL末尾が残り得る。画面を閉じることと評価の停止は別であり、必要なら`viewer.close(stop=True)`を実行する。ノートブックのビューア生成セルを再実行すると、以前の同ビューアの評価は停止する。

`USE_MODEL=False`はモデルなしの操作確認。自律的判断の実験とは分けて扱う。モデルの走行も通常の評価と同じ時間・操作予算を使用する。

## 表示内容

|表示|読めること|
|---|---|
|直前と最新の観測|実際の前後画面。赤丸は操作対象だった画面上のクリック座標|
|操作|方向／クリックと座標、選択のみ・送信・受付・次観測の有無|
|DECIDE / RUN|状態、処理中／完了、イベント時刻とstep|
|状態の入力／出力|作業記憶、前回結果、選んだ仕事、処理結果・エラー。処理中なら出力待ち|
|選択イベント|その瞬間に書かれた元のレコード|
|HTTP入力／モデル応答|その時点までの直近の要求と応答。各レコードのstep・時刻で対応を確認|
|ツール・学習|スキルのロード、引数、成功／失敗、経験・候補・評価等の直近イベント|
|記録済みアニメーション|当該観測が受領した遷移の途中画面。ゲームを再実行しない|

クリックの重ね描きは記録された座標変換を使用する。画面変化や操作受付は、予測の的中やゲーム攻略の成功とは別である。

## 新しく追加したログ

`<run>.states.jsonl`に状態入場時の入力と退出時の出力、実行終了を逐次保存する。状態入場はLLM呼出し前に書き出すため、応答待ちを表示できる。各ジャーナルへ同一走行内の連番`sequence`も付け、同時刻のイベントを並べられるようにした。

状態ごとの入出力は既存の制御境界で収集し、LLMに可視化のための追加説明を生成させない。ログの読取りや再生はゲーム環境・モデルを呼び出さない。記録された要約はモデルの出力であり、非公開の内部思考を復元したものではない。

## 制約

トークン単位のストリームではなく、ログの追記をポーリングする表示。モデルの生応答は該当する呼出しの記録が完成した時点で読める。RUNなど一瞬の状態はライブで見逃してもイベント再生で確認できる。記録済みアニメーションの再生間隔は表示用で、実際の経過時間ではない。

起動にはJupyterのPython環境とローカル評価環境が必要。既定のDocker環境ではipywidgets 8.1.5を確認済み。別環境で`Error displaying widget`になった場合は、その環境のJupyterLabとipywidgetsの対応を確認する。大きな履歴はゲーム単位のcognitionディレクトリを指定すると読み込み量を減らせる。

## 開く際にFile Load Errorになる場合

`Unhandled error`だけでは原因を判別できないため、`docker compose logs dev`を確認する。今回の環境ではノートブック取得がHTTP 200でも、チェックポイント作成がHTTP 500になっていた。原因は`notebooks/.ipynb_checkpoints`がコンテナのroot所有で、Jupyter実行ユーザーに書込み権限がなかったこと。保存先の所有者を修正し、取得200・チェックポイント作成201を確認した。

`make repair-perms`は`notebooks/`全体とチェックポイントも修正対象に含む。所有者を修正した後はJupyterLabでノートブックを開き直す。ノートブックのJSON検証やカーネル実行だけでは、このブラウザ経由の保存処理は検証できない。
