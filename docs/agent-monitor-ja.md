# 最新ステートマシンを確認する

[観測ノートブック](../notebooks/agent_observatory.ipynb)を上から実行すると、**ログがなくても最新実装の全体グラフ**を表示する。

## ウィジェットが表示されない場合

`Error displaying widget: model not found` は、保存済み出力が参照するウィジェットIDを現在の表示環境で復元できないときに発生する。ここでの「model」はLLMではなく、操作画面のウィジェットを指す。

初期化・表示モジュールの再読込み・操作画面の生成は1つのコードセルにまとめている。カーネル再起動・再接続後は、このセルを実行するか、JupyterLabの **Run → Run All Cells（すべてのセルを実行）** で画面を作り直す。改善しなければ **Kernel → Restart Kernel and Run All Cells** を実行する。このノートブックではゲームの再実行は行わない。リポジトリには実行出力を消した状態で保存し、過去のウィジェットIDを持ち越さない。

## 全体図

実行側の `agent/cognition/machine.py` にステートと条件付き遷移を定義し、実行時のルーティングと表示で共有する。観測、熟考、スキル選択、手順実行、8による熟考への復帰、7による段階移行、操作待ち、終了を表示する。ADKのDECIDE/RUNはこれらを呼び出す制御骨格であり、タスクの全体図とは区別する。

- 青いステートはLLM判断、緑はホスト処理、赤は終了。
- 橙の破線は差し戻し。グラフ上部のチェックでスキル・差し戻し・停止の経路を薄くし、通常経路を追える。
- 矢印の番号は下の遷移条件一覧に対応する。矢印にカーソルを置いても条件を確認できる。
- 時間・操作予算・受付不明など、全体に適用する停止条件は赤い欄にまとめる。
- 各タスクの指示と出力契約は下部で開ける。

コードの編集後は**最新の構造を再読込**で反映する。ログ再生時にもソースの変更を確認する。ソースはASTで読むため、表示のためにモデルやエージェントを起動しない。TASKSとステート宣言が一致しない場合はエラーになり、古い図へフォールバックしない。

## 実行記録を分析する

1. 最新実装で `make benchmark` を実行し、`outputs/evaluations/<評価ID>`に記録を作る。
2. ノートブックで**評価ID → ゲーム → 読み込む**を選ぶ。
3. **問題箇所**から差し戻し・出力エラー・停止へ移動する。
4. 同じ時点の入力、モデル応答、ホスト判定、前後画面、ノートを照合する。「測定・計画を読む」で、物体別測定、意味回答、未処理・保留件数、目標、因果メモ、実行段階と照合履歴を確認できる。

通常一覧は`outputs/evaluations/`だけを対象にし、manifestの`created_utc`が新しい順に並べる。実行時のモデル名に加えて、認識方式（初回SAM＋画素追跡など）と、保存された`agent/`の全ソースハッシュが現在の実装に一致するかを表示する。同じQwen名でも古い認識・計画処理の記録を最新と誤認しないための表示で、モデル重みや推論サーバーの完全一致を保証するものではない。グラフは現在のソース、再生内容は評価時点の記録である。

「測定・計画を読む」には、その時点のSAMの`status`・`called_this_frame`・候補回収不足を表示する。`sam_initial`の設定だけでSAM成功とは扱わず、`unavailable`や`skipped_budget`もそのまま示す。

2026-09-29の最新確認は`20260928T155108137699Z`（評価IDはUTC時刻）。現行QwenとSAMを使い公開3ゲームを各6操作・90秒以内、1観測の判断上限45秒で実行した。3ゲームとも初回SAMは`ready`。ただし最初の判断が時間切れとなり、ゲーム操作は0回だった。認識結果から計画・記憶参照へ進んだ経路と停止理由を確認するログであり、攻略成功や移動後の接続検証ではない。

過去の比較検証は通常一覧から外した。参照する場合はNotebookの初期化先を、例えば`BenchmarkReplay(ROOT / "outputs/measured-runtime-20260928", source_root=ROOT)`へ変更する。調査資料が参照する旧通常評価は`outputs/history/evaluations/20260926T172310706477Z`へ移動し、資料の参照先も更新した。整理記録は[observatory-cleanup-20260929.json](../outputs/observatory-cleanup-20260929.json)。研究用の生ログは保持している。

「表示時点までの実行経路」には未来の判断を混ぜない。実行時のモデル名と一観測の判断時間と計画出力の修正回数も表示する。画面の赤丸は選択したクリック位置であり、成功した位置という意味ではない。

最新形式はmanifestの`observatory_schema: 3`を持つ。旧ログの変換・過去構造との切り替えは廃止した。読めない記録はエラーとする。旧評価ログ41件を削除済みで、削除一覧は`outputs/state-graph-cleanup.json`。

グラフ自体は実行記録が空でも利用できる。ノートブックは保存ログの読取り専用で、評価やモデルを自動実行しない。

熟考は状況理解・前提条件の逆算・実行手順への具体化・結果照合の4状態。計画パネルには目標の依存関係、完了候補と確認状態、手順の起動ID、照合の根拠を表示する。
