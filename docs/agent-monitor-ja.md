# 最新ステートマシンを確認する

[観測ノートブック](../notebooks/agent_observatory.ipynb)を上から実行すると、**ログがなくても最新実装の全体グラフ**を表示する。

## 全体図

実行側の `agent/cognition/machine.py` にステートと条件付き遷移を定義し、実行時のルーティングと表示で共有する。観測、機械判定、LLMの8タスク、実験検証、スキル実行、差し戻し、操作待ち、終了を表示する。ADKのDECIDE/RUNはこれらを呼び出す制御骨格であり、タスクの全体図とは区別する。

- 青いステートはLLM判断、緑はホスト処理、赤は終了。
- 橙の破線は差し戻し。グラフ上部のチェックでスキル・差し戻し・停止の経路を薄くし、通常経路を追える。
- 矢印の番号は下の遷移条件一覧に対応する。矢印にカーソルを置いても条件を確認できる。
- 時間・モデル予算・受付不明など、全体に適用する停止条件は赤い欄にまとめる。
- 各タスクの指示と出力契約は下部で開ける。

コードの編集後は**最新の構造を再読込**で反映する。ログ再生時にもソースの変更を確認する。ソースはASTで読むため、表示のためにモデルやエージェントを起動しない。TASKSとステート宣言が一致しない場合はエラーになり、古い図へフォールバックしない。

## 実行記録を分析する

1. 最新実装で `make benchmark` を実行し、`outputs/evaluations/<評価ID>`に記録を作る。
2. ノートブックで**評価ID → ゲーム → 読み込む**を選ぶ。
3. **問題箇所**から差し戻し・出力エラー・停止へ移動する。
4. 同じ時点の入力、モデル応答、ホスト判定、前後画面、ノートを照合する。

「表示時点までの実行経路」には未来の判断を混ぜない。実行時のモデル名と一観測あたりの判断・HTTP上限も表示する。画面の赤丸は選択したクリック位置であり、成功した位置という意味ではない。

最新形式はmanifestの`observatory_schema: 1`を持つ。旧ログの変換・過去構造との切り替えは廃止した。読めない記録はエラーとする。旧評価ログ41件を削除済みで、削除一覧は`outputs/state-graph-cleanup.json`。

グラフ自体は実行記録が空でも利用できる。ノートブックは保存ログの読取り専用で、評価やモデルを自動実行しない。
