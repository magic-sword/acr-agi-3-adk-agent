# 現行エージェントのローカル評価と改善案

2026-09-24 10:48 UTC（19:48 JST）に `make benchmark` を実行した。モデルはローカルQwen3-VL-4B-Instruct、公開3ゲームを各1試行、最大12操作・1レベル・判断90秒・プロセス110秒で測定した。実行中のエージェント変更はない。

|---|---:|---:|---:|---:|---|
|ls20-9607627b|0.0|0|0|9.87|有効な操作提案を生成できず停止|
|vc33-5430563c|0.0|0|12|84.54|操作数上限|
|ft09-0d8bbf25|0.0|0|1|15.24|有効な操作提案を生成できず停止|

全ゲームの公式SDKスコアカードを取得し、平均は **0.0**。合計13操作、ワーカー時間109.65秒。初期化RESETは操作数に含まない。公開ゲームの全レベルを分母とする短時間評価であり、Kaggleの非公開スコアの推定値ではない。

## ログで確認した問題

### 1. 型検証に成功しても、実行可能な提案とは限らない

モデル判断33件すべてがJSON型検証に成功した。一方、ls20では実験記述の欠落で1回失敗し、修正応答では使えないCLICKを提案して停止した。モデル入力の `available_actions` は `UP, DOWN, LEFT, RIGHT` であり、入力への操作一覧の欠落ではない。ft09では `probe requires action and discriminating experiment` が3回発生し、2手目で停止した。

改善案：状態別の応答契約でPROBEの実験を必須にし、操作enumを観測の使用可能ボタンに絞る。修正要求もモデル側のボタン名と不足項目で伝える。ホスト側の最終検証は維持する。固定した失敗観測で、合法な操作と異なる予測を持つ実験が得られるかを先に確認する。

### 2. 観測内容が記憶に入らず、探索から計画へ進まない

解析可能なOBSERVE応答15件すべてでfactsとgoalが空、unknownsは `control mapping` のまま。全ゲームでPLAN訪問は0回だった。`agent/cognition/engine.py` のrouteは、goalが空またはunknownsが残るとPROBEを選ぶため、この出力のままでは計画に進めない。

改善案：空配列を示す観測例を見直し、見えている対象の位置・色・関係と前回からの変化を短く回答させる。目標は証拠付きの仮説として扱い、形式を満たすために捏造させない。保存画像で観測抽出を単独評価し、事実の正確さを確認してからゲームを再測定する。例示への追従が原因という見方は仮説であり、今回だけでは画像認識・プロンプト・モデル能力の寄与を分離できない。

### 3. 同じクリックと上端表示の変化が探索を空回りさせる

vc33の12操作は全件 `ACTION6(x=32,y=32)`。3ゲームを通じてmove_cursor呼び出しは0回だった。vc33の連続観測12組では、変化はすべてy=0の1〜2画素に限定され、y=1〜63は変化していない。保存PNGでも中央カーソルを確認した。

画面ハッシュ自体は変わるので、自動集計の `unchanged_action_repeats=0` ではこの反復を検出できない。実験の `frame_changed` はtrueになるが、盤面内の対象に作用した証拠にはならない。上端が何を意味するかは今回の観測だけでは断定しない。

改善案：対象物・領域ごとの変化と、同じ操作・座標の反復を併記する。上端を全ゲームで一律除外せず、対象の変化が確認できない場合に別の対象候補へカーソルを動かす実験を選ぶ。カーソル移動済み・対象確認済みかを記録し、初期座標への無根拠な連続クリックを検出する。

### 4. 実験結果は記録されても、有用な仮説の更新につながらない

実行済み13操作の検証結果はすべてunknown。これは失敗率100%という意味ではない。effectsが空なので総合結果がunknownになる一方、vc33では実験のalternativesに `changes=[true], unchanged=[false]` が記録されている。観測応答はそれを使ってunknownsや仮説を更新していない。

改善案：どの実験候補が観測と一致したかを、効果予測のsupported/contradictedとは分けて記憶に保存する。次の実験選択で同じ問いの反復を抑える。単なる画面変化をクリアへの進展とみなさず、制御と対象の関係を検証する述語へ具体化する。

### 5. ツール接続と、ツールを有効に使うことは別の課題

vc33ではlist_skillsとload_skillが各1回、observe_currentが7回。ls20とft09ではツール利用がなかった。vc33のモデル判断24件に対してHTTP要求は33件、モデル時間は83.59秒だった。ツールは利用できているが、観測内容の改善や対象選択には結びついていない。

改善案：必要なスキルが判断前に読まれたかを測り、同じ画面の再読が新しい情報を与えたか確認する。読み込みの再利用や入力の短縮は、その後に同条件で計測する。今回の主な停止原因はls20とft09の提案不良であり、時間上限を増やすだけでは解消しない。

## 初回測定との比較と次の評価

[初回測定](local-evaluation-20260924-ja.md)と同じ上限・同じゲーム版で、平均スコアは0.0のまま。操作数はls20が11→0、vc33が0→12、ft09が10→1。vc33の座標欠落による停止は今回発生しなかったが、クリアへの進展はなかった。複数の実装変更を含む各1試行なので、個別変更の因果効果や安定した性能差とは断定しない。

次は **操作・実験の契約 → 観測の具体化 → 実験結果の記憶と反復回避 → 推論費用** の順に、変更を分けて評価する。保存した失敗観測で合法操作率・意味検証成功率・観測事実の正確さを確認し、同じ3ゲーム・同じ上限で再測定する。スコア、到達レベル、停止理由に加え、空観測率・同一座標反復・対象領域の変化・PLAN到達・HTTP回数を比較する。
